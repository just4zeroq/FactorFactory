## 1. 不变量 I1–I61

| 编号 | 陈述 | 让步后的失效模式 | 机器检查点 |
|---|---|---|---|
| **I1** | 配置在编译期完备，运行期无任何默认兜底 | 拼错实现名 → 静默换算法 → 结论不可复现 | C1–C22 全通过；方案无未解析占位 |
| **I2** | 只有唯一裁判能发布结论，且不提供宽松默认 | 判据被分散打折，或严格模式悄悄跑通 | 能力签名不含结论出口；缺注入即拒绝执行 |
| **I3** | 不可逆事件绑定执行，只发生一次 | 留出窗口被重复揭示，样本外退化成样本内 | 事件账本查重；恢复执行读取已记录结果 |
| **I4** | 口径冻结，单步锚定同一方案 | 单步与整体口径漂移，产物混合后无法解释 | 单步入口拒绝重新编译；`policy_digest` 全链一致 |
| **I5** | 工位间只传不可变、可落盘、可重建的 Parcel，指纹链完整 | 单步拿不到输入；重建失败降级成空产物却显示成功 | 依赖校验；重建失败即 `failed` |
| **I6** | 构成性参数变更等于新试验族，计数不复用 | 隐式模型选择绕过统计门槛 | 族声明校验；全局计数单调 |
| **I7** | 整体与单步共用执行器与裁决者；单步是观察不是重试 | 出现第二套逻辑与「重跑到通过」的通道 | 单入口；单步产物标 `origin=step` |
| **I8** | 失败显式：非零信号 + 失败状态 + 可读原因 | 流水线显示成功，结论建立在空输入或零折验证上 | 退出码、结构化记录、`skipped(reason)` 区分 |

| **I11** | 工位标识与契约版本稳定，变更必须显式 | 历史执行无法复现 | 规格表版本校验；恢复前指纹比对 |
| **I12** | 经济口径单一来源，认证回灌同一判据 | 便宜口径通过裁决、昂贵口径回测；用展示指标代替判据 | C9；认证结论复用同一判据 |
| **I13** | 共享事实不可变、内容寻址；执行期对共享仓零写入 | 数据刷新静默改写历史结论 | 版本清单与校验和；工位只读权限 |
| **I14** | 别名只在编译期解析成精确引用，运行期不得再解「最新」 | 同一次执行的不同工位读到不同数据版本 | 引用冻结；运行期无别名解析路径；C11 / C12 |
| **I15** | 运行时环境快照必落盘，凭据只存引用名 | 同方案两次执行产物不一致却无从排查；凭据泄露 | 环境摘要字段校验；蓝图/料包/日志脱敏扫描 |
| **I16** | 每工位独立目录；日志与产物同目录同指纹；维护日志归属共享仓 | 料包失效时无法判断日志可信度 | 工位目录契约校验；三条日志流关联键可反查 |
| **I17** | 组合只消费编译期冻结的组合域；纳入规则只按身份与状态 | 无限次免费模型选择；选择偏差继承且门槛被稀释 | `domain_digest` 进口径锚点；组合工位无增删成员权限 |
| **I18** | 每个已登记成员带可用时间；拟合窗口起点不早于域内最晚可用时间 | 把未来才发现的因子放进历史区间，或全期拟权重再在同一段评估 | 编译期校验 `fit_window_start`；窗口不足即失败 |
| **I19** | 所有挖掘算法归一到统一候选结构；算法无评估、判定、计数出口 | 算法自带筛选，实际试验数不可见；判据被分散 | 四方法签名校验；`Candidate` 字段白名单；AC21 |
| **I20** | 试验计数只认去重后的实测候选数，不认配置声明的数量 | 算法多产候选而计数不增，多重检验门槛失真 | Budget 取 `CandidateSet.count`；C14 配额双重校验 |
| **I21** | 多算法共用一个候选集合与一次计数；内置因子整批声明、同等裁决 | 按结果挑算法、逐条加先验公式，等于免费刷结论 | 一次 Budget；`generator` 不得分池分族；AC22 |
| **I22** | 构造与成本口径只有 `caliber` 一个来源，任何工位不得自带 | 判据用一套构造、部署用另一套；两份参数迟早不一致且无人发现 | C20；`caliber_digest` 进 `policy_digest`；AC24 |
| **I23** | 单因子评估与组合评估共用同一构造与成本实现，差异只允许是成员数与成员身份 | 「净成本后可交易」这句话在单因子这一层失去含义 | 同一 `allocate@v` / `backtest@v` 与同一参数；AC24 |
| **I24** | 组合的拟合、隔离、评估三段窗口互不重叠且都在搜索区间内；可交易结论只在认证段产生 | 全期拟权重再同段评估；用探索段表现发布结论 | C21；`PortfolioParcel` 带证据等级；AC25 / AC27 |
| **I25** | 重叠标签不得当独立观测；`rebalance < horizon` 必须显式声明处理方式 | 标准误低估、显著性虚高，出现假晋升 | C22；报告中必须出现所用策略；AC26 |
| **I26** | 回测的 `summary` 与 `full` 两档读同一份 `Ledger`；判据用的净收益与报告用的净收益是同一个数 | 为「性能」另写向量化捷径 → 两套成交逻辑 → 判据与报告互相矛盾且无从发现 | 两档必须由同一实现产出；`full` 的聚合必须能还原出 `summary` 的每一项；AC28 |

| **I31** | 每条命令声明 mutation 等级；`writes_ledger` 以上必须二次确认 | 无确认的 `promote` / `reveal` 会不可撤销地改全局单调 | 无 `--yes` 调 `promote` → 拒绝，退出码 2（用法错误） |
| **I32** | `--json` 输出是稳定契约；`ok` 与 `exit_code` 必须一致 | 退出码恒 0 的历史问题；脚本与 Web 都依赖这一层 | 逐命令跑 `--json` 校验一致 |
| **I33** | 年化不得依赖任何库的默认值；加密一律 365 天/年、1440 分钟/日 | 回测曾不传 `calendar`，Sharpe 少报 20.4%（实测 0.2091 vs 0.2517） | `build_backtest_config` 必须传 `calendar="crypto"`；AC33 |
| **I34** | 资金费只按事件求和，不得按固定周期乘；`caliber` 里不得出现 `funding_interval_hours` | 结算周期实测有 1h/4h/8h 三种且同一合约会变；按常数乘会系统性错算持仓成本 | 配置校验拒绝该字段；AC34 |
| **I35** | 面板列集是开放集；配置声明的流缺失时 fail-closed | 固定五列的 panel 让「加一个加密因子」变成改代码，扩展点承诺失效 | 声明 `basis` 但供给层无文件 → `E1014` 中止；AC35 |
| **I36** | 交易日历不得参与任何业务判断 | 加密 24/7，用股票日历判「未收盘」或「是否交易日」会直接算错 | AST 扫描：除 ml4t 内部，不得 import `pandas_market_calendars`；AC36 |
| **I37** | 适应度通道只存在于 `fit`，只读 `mine_slice`，只返回标量或向量 | 通道若出现在 `generate` 或返回结论性字段（p 值、成本后收益），算法就会朝「更容易过闸门」搜索——每步都合法，只是目标被换掉 | `generate` 的入参里没有 `ctx`；`fitness` 返回值形状检查；AC37 |
| **I38** | 试验计数的单位是去重后的 `candidate_id`，包含 `fit` 内评估过的候选 | 只登记最终种群 → `n_trials` 被低估一到两个数量级 → DSR 门槛下调 → 假晋升 | 一次执行内 `Budget` 累计值 ≥ `CandidateSet.count`；GP 跑 300×10 → 累计应显著大于 300；AC38 |
| **I39** | 自适应算法的全局随机状态必须隔离：进入快照、退出还原、禁止并发 | deap 算子内部用全局 `random`；两次并发 `fit` 会互相污染，同 seed 结果不同却无从发现 | `needs_fitness=true` 且检测到并发 → `E2009`；跑完比对 `random.getstate()`；AC39 |

这三十九条不是「最佳实践」，是**可机器检查的结构约束**。每条对应一个具体检查点；检查点缺失的条目视为未实现。

## 2. 经济口径单一来源

以下量必须在 `caliber` 块里各有一个权威值，所有工位只读：标签跨度、再平衡周期、入场价口径、成本档位与扣减方式、资金费结算周期、年化基准、有效截面宽度下限、中性化回归窗口、构造约束（分位形式、权重方式、单标的上限、净敞口、换手上限、最小成员数）。

**判据**：如果裁决阶段认为一个信号「净成本后可交易」，而组合阶段用另一套成本假设把它算成亏损，就是 I12 与 I22 被违反。这类不一致必须在编译期拦下（C9 / C20），而不是在报告里附一句提醒。

「构造」与「成本」两个子块之所以都要放进同一个 `caliber`，是因为它们**不能分开设计**：成本的唯一输入是换手，而换手由构造决定。把构造留在工位参数里、只把成本放进口径块，等于允许「换一种建仓方式」而成本假设不变——成本会算错，而且错得看不出原因。

设计上不追求「让门槛更容易通过」。如果信号强度不足以跨过门槛，正确动作是提升信号量级或降低噪声，不是降低判据、不是清零计数、不是把一次探索拆成多个族来分散计数。

## 3. 组合域：哪些因子有资格进组合

### 3.1 结论

> 组合工位的输入不是「本次候选」也不是「全局因子库」，而是一个**编译期预注册、随方案冻结的 `CompositionDomain`（组合域）**。全局登记只是来源之一，本次候选是另一个来源；**运行期按表现挑成员一律禁止**。

| 层 | 名称 | 性质 | 职责 |
|---|---|---|---|
| 来源 | 全局登记 | 跨执行、只追加、只读 | 登记每个已发布因子的身份、血缘、口径、可用时间、裁决证据与状态 |
| 选择 | `CompositionDomain` | 编译期冻结，进 `policy_digest` | 按**身份与状态规则**确定成员集合 |
| 执行 | Portfolio 工位 | 运行期，只读域 | 去共线 → 全期一次性拟合固定权重 → 约束持仓 → 净成本后表现 |

两个极端都错：**只用本次**，分散化收益极低，且每次重拟权重会让同一因子跨执行权重漂移，历史结论不可比；**无条件用全部**，会引入四类污染。

### 3.2 四类污染

1. **选择偏差继承**：登记里每个成员都从大量试验中挑出来，K 个这样的成员 ≠ K 个独立信号。多重检验门槛按累计试验次数算，不能靠 √K 稀释；组合产物必须回灌同一裁判。
2. **口径混合**：历史成员可能来自不同池、成本档、跨度、试验族；`policy_digest` 只能锚一个口径。域的纳入规则必须要求口径摘要一致；确需跨口径只能显式声明为新预注册枚举与新试验族。
3. **知识前视**（最易漏）：数据本身干净，但「该用哪个表达式」当时不存在。每个成员必须带 `available_from`——首次通过裁决、可被使用的时间，不是被计算出来的时间，更不是数据末端时间。
4. **域选择即模型选择**：运行期「挑表现最好的五个」等于无限次免费试验。

> 判据：**如果一条纳入规则需要看因子的历史表现才能回答，它就不是纳入规则，是一次试验。**

### 3.3 可用时间与三段窗口

| 概念 | 定义 | 是否随时间变 |
|---|---|---|
| 域 | 冻结的**成员身份集合 + 各自 `available_from`** | 不变 |
| 可用视图 | 域中满足 `available_from ≤ t` 的子集 | 由冻结域确定性派生，不是新自由度 |
| **fit 窗口** | 估权重的区间；起点 **`fit_window_start ≥ max(域内成员的 available_from)`** | 固定 |
| **embargo** | 夹在 fit 与 eval 之间的隔离段，长度 ≥ `horizon` | 固定 |
| **eval 窗口** | 算净表现的区间；起点 ≥ fit 终点 + embargo，终点 ≤ 搜索区间末端 | 固定 |

只约束拟合起点是不够的：不约束拟合终点与评估起点，字面上就允许「全期拟权重、同段评估」——那是组合层自制样本内。三条约束由 C21 在编译期校验，细化见 `06-evaluation.md` §8。

拟合窗口被推到「所有成员都已可用」之后，窗口内可用视图恒等于整个域，成员集合不再变化、权重无需随时点重学。代价必须显式暴露：

> **纳入的历史成员越新，可用的评估窗口越短。**

窗口不足只能缩窄域或放弃组合，禁止「全期拟权重再在同一段评估」。

还有一条等级约束：**eval 段在搜索区间内，因此组合净表现是样本内构造诊断，不是可交易结论。** 可交易结论只在认证段用同一判据复算后产生（I24）。

### 3.4 域字段与预算

| 字段 | 说明 |
|---|---|
| `scope` | `local_only` / `registered_only` / `hybrid`，构成性参数 |
| `inclusion_rule` | 预注册枚举；只允许身份与状态条件，**禁止表现类条件** |
| `members` | 标识、表达式版本、`available_from`、口径摘要、血缘、裁决证据引用、退役状态 |
| `fit_window` | `{start, end}`，起点由成员可用时间下界推导，编译期校验 |
| `embargo` | 隔离段长度，≥ `horizon` |
| `eval_window` | `{start, end}`，落在搜索区间内 |
| `domain_digest` | 成员集合与版本的指纹，进 `policy_digest` |
| `forbidden` | 运行期增删成员、按表现重排、窗口内动态重拟合权重、eval 与 fit 重叠 |

成员谱系不可为空。`local_only` 不新增计数；涉及全局登记时，**域声明整体预注册一次**，不重复计成员各自历史预算，但也不得声称「成员免费所以 K 大、门槛低」；枚举多个域各自独立计数，禁止自动遍历。

### 3.5 默认、退役与另一种歧义

默认 `scope = local_only`（偏差最小、口径天然一致、可复现最强）。启用 `hybrid` / `registered_only` 需三个前提全满足：成员可用时间/口径/证据/血缘完整可校验；编译期口径一致且 `domain_digest` 进锚点；`fit_window_start` 之后的评估窗口足够长。

成员状态 `active / watch / retired` 由**认证段之外、预注册的监控规则**只追加写回，组合层只读；域冻结后评估窗口内成员不因退役变化，保证单步与复现稳定。

若「自己的因子」按**生成范式**理解，答案同样是不分家：生成器只是不同的命名实现，是实现细节不是统计分组单位。所有范式的产出进同一候选料包、同一试验族、同一漏斗、同一裁判；`generator` 仅作谱系元数据，不得成为分池、分族或分账依据。

### 4.1 AC63：什么叫「验收通过」

**通过 = 两个条件同时成立**，缺一不可：

1. **机制正确**：AC1–AC62 全绿；三处失败演示各有指定错误码、退出码且无副作用；试验计数不少记。
2. **已知答案对拍**：在 V5 自采数据冻结的**黄金面板**上，`mom60@5bar`（基线 `h=5 / rebalance=5 / next_close`）的全链指标与手写 pandas 独立复算相对误差 ≤ `1e-9`（决定论量：`gross_sharpe` / `gross_return` / `sr` / `turnover` / `n_periods`），且流水线复跑与冻结期望值漂移 ≤ ±10%；`n_trials` 等于预注册枚举的实测去重候选数。**不依赖 V4 的任何内容**（2026-11-17 裁决：V4 数据与实测值 0.675 只作量级背景，不参与判据）；细化见 `14-test-strategy.md` §4.4。

`passed=0` **不构成失败**。当前面板上最强朴素信号 0.675 远低于 `n_trials=255` 的 DSR 门槛 1.53，系统会正确拒绝一切候选。验收看的是「0.675 有没有被正确算出来」，不是「有没有因子过闸门」——把顺序倒过来，压力就会变成调低 `dsr_min`、清零 `n_trials` 或拆分试验族，而这三件事正是 V4 假成功的来源（§2）。

## 5. 演进路线

| 阶段 | 交付 | 验收 |
|---|---|---|
| **E0 规格化** | 八步规格表、能力目录（名字清单）、基线 `v1`、四区布局与共享仓版本契约 | `flow stations` 与 `flow explain` 可用；此时不执行任何工位 |
| **E1 编译** | 三层合并、Blueprint、`caliber` 块、四个锚点指纹、别名固化为 pin、组合域冻结、名字与参数解析、子调用图、C1–C22 校验 | AC1、AC2、AC17、AC18、AC23–AC26 通过 |
| **E2 执行器** | 唯一 `execute()`、调用单四通道、Parcel 落盘、工位独立目录与日志归属、环境快照、唯一裁判 | 整体跑通；AC3、AC6、AC9、AC10、AC13–AC16、AC19、AC27 通过 |
| **E3 单步** | 依赖/失效校验、隔离产物、状态机、事件绑定、命令面 | AC4、AC5、AC7、AC8 通过 |
| **E4 能力扩容** | 新增挖掘算法与内置因子清单；其余模块只升版本 | AC11、AC12、AC20–AC22 通过 |

顺序理由：E1 是 E2 的前提（没有冻结口径，产物指纹没有意义）；E2 的料包化是 E3 的前提（只要还有跨工位活对象，单步就不可能成立）；E4 可以长期渐进，先固定默认实现把统计纪律立住，再按两个扩展点逐步扩充。

**最小优先集**：若资源有限，优先把「编译期冻结 + 料包化」做实。这两项同时是「整体跑可信」与「单步可跑」的共同前提；算法扩容可以后补。反过来，先做插件框架而跳过这两项，会得到一条「很灵活但结论不可信」的流水线。

| # | 问题 | 倾向 | 影响面 |
|---|---|---|---|
| Q1 | 回测是否拆成独立工位？ | **否（已收敛）**：`backtest` 是底层共享能力（完整引擎 + `Ledger` + 两档聚合），被证据、裁决、组合、认证四处按同一口径调用 | 单步想重放成本情景时走能力级诊断通道 |

| Q6 | 认证段允许几种切分并存？ | **只允许预注册一种主策略（已收敛）**：多切分并存的实际后果是「用最好看的那条发布」，这属于把选择权藏进报告；其余切分只能跑只读诊断，且诊断结果不得进入任何发布路径 | I3、I12 |
| WQ1 | 数据版本变更是否等于新试验族？ | 否：事实演进不是研究自由度 | I6 与计数 |
| WQ2 | 刷新后允许用同一计划重跑搜索工位吗？ | **不允许（已收敛，A25 / I59）**：`blueprint` 固化 `supply_digest`，数据版本变化后同一计划重跑 `Search` → `E1009`；新数据只进认证段 | I3、I9、单步边界 |
| WQ3 | 供给维护链是否独立于流水线？ | **是**：维护不产生执行、不进状态机；外层调度串联「维护 → 编译 → 执行」 | I13、I14、命令面 |
| WQ4 | 事实种子是否永久保留？ | 默认永久；引入保留期前须保证无归档引用指向待删版本 | 复现定义与存储成本 |
| WQ5 | 缓存命中能否跳过全局登记？ | 不能：命中只跳过计算，不跳过登记 | 计数单调与 I9 |
| CQ1 | 组合域默认范围取哪个？ | **`local_only`（已收敛，A26 / I60）**：跨执行域成员未显式声明 → `E1018`；声明后仍需三个前提全满足 | I17、可复现性 |
| CQ2 | 允许跨口径成员吗？ | 默认拒绝；确需时作新预注册枚举与新试验族 | 口径锚点与 I6 |
| CQ3 | 域内成员数是否设硬上限？ | 设，并与有效评估窗口长度联动 | 防止假性分散化 |
| CQ4 | 退役监控放在哪一层？ | 认证段之外的独立规则，只追加写回全局登记 | 组合层权限与复现稳定性 |
| MQ1 | 算法新引入算子或字段时，是否一律新试验族？ | 是：搜索空间变了就是新实验 | I6、A18 |
| MQ2 | 非确定性算法能否作为默认？ | 否：默认必须 `deterministic=true` | 复现与 I10 |
| EQ1 | 标签层已做流动性中性化、构造层又用流动性加权，是否禁止？ | **不禁止但编译告警（已收敛，A28）**：可能是有意设计，必须写进报告而不是静默抵消 | I22、可解释性 |
| EQ2 | 认证段是否复用组合层的同一套构造与成本参数？ | **是**：同一 `caliber_digest`；只允许数据不同，不允许口径不同 | I23、I24 |
| EQ3 | 容量（capacity）是否进入判据？ | 不进：容量是诊断与规模可行性，不是显著性判据；混进去会让「大资金才算 alpha」变成新的自由度 | 判据单一性 |
| EQ4 | `width_policy=drop` 丢弃的时点数是否设上限？ | **20%（已收敛，A27 / I61）**：超过即 `E3003`，而不是「丢一点继续跑」——静默缩短研究窗口会让结论看起来更好；丢弃数与区间写进 `quality_report` | I25、报告完整性 |

Q1–Q6 六条已全部收敛。WQ2、CQ1、EQ1、EQ4 已从「倾向」升为 **A25–A28 裁决 + I59–I61 不变量**，有机器检查点；其余 WQ / CQ / MQ / EQ 条目保持明确倾向，不改变配置模型、执行语义与不变量。**开放问题不再阻塞实现**：S0–S4 阶段不需要新的裁决。

## 8. 术语表

| 术语 | 含义 |
|---|---|
| **Baseline@vN / Plan / Override** | 三层配置来源：完整默认清单 / 研究计划 / 命令行临时覆盖 |
| **Blueprint** | 编译后冻结的只读执行方案 |
| **Parcel** | 工位间唯一合法的、不可变且落盘的产物包 |
| **Ticket** | 一次执行的状态主体与口径锚点 |
| **Station** | 有输入/输出/副作用契约的执行工位，共八个 |
| **名字 + 参数** | 配置单的唯一形态；编排层不接触实现细节 |
| **能力目录 / 调用单** | 名字到 `实现@版本` 的对照表 / 一次调用的完整输入 |
| **四档名字空间** | 开放 / 封闭多选 / 单实现 / 唯一且不可配 |
| **AlgorithmSpec** | `describe()` 返回的算法声明：参数定义、字段、算子、输出类型、配额 |
| **MarketView** | 算法唯一能看到的只读市场投影，不含评估窗口与判据 |
| **FittedState** | 有状态算法的可落盘、可重建拟合结果 |
| **Candidate / CandidateSet** | 统一候选结构 / 去重后的候选集合；`count` 是**交付**计数，与 `fit` 内评估合并去重后才是 `n_trials` |
| **Lineage** | 候选的父代与算子，用于血缘、去重与审计 |
| **Sentinel** | 唯一有权发布结论的裁决者 |
| **Event** | Reveal / Budget / Publish，绑定一次执行的不可逆动作 |
| **Constitutive / Operational** | 构成性参数：改了等于换实验 / 操作性参数：只影响怎么算完 |
| **policy_digest** | 构成性参数子集的指纹，全链口径锚点 |
| **stale / origin** | 因上游或口径变化不再可信的状态 / 产物来源标记 |
| **Charter / Depot / Ticket / Scratch** | 四个存储区：只读章程 / 共享仓 / 执行区 / 可弃暂存 |
| **Seed / Derived / Register** | 共享仓三类资产：不可重建事实 / 可重算派生物 / 只追加全局登记 |
| **Pin / supply_digest / SupplyRef** | 编译期固化的事实版本引用 / 其指纹 / 进入料包输入链的一等引用 |
| **Envelope** | 运行时环境快照，含可记录面与凭据引用面 |
| **CompositionDomain** | 编译期冻结的组合成员域；`domain_digest` 进口径锚点 |
| **available_from** | 成员首次通过裁决、可被使用的时间；划定拟合窗口起点 |
| **backtest / detail** | 回测能力；`summary`（判据用摘要）与 `full`（逐笔、账本、归因）两档输出 |
| **Ledger** | 回测产出的唯一账本：逐时点逐标的的目标权重、成交、费用、资金费；两档输出都从它聚合 |
| **evaluate / Exposures** | 表达式 → 横截面暴露的唯一实现 / 其产物，含有效掩码与节点缓存统计 |
| **flow run / flow station** | 整体执行 / 单步执行的编排入口 |
| **caliber / caliber_digest** | 口径块（执行 / 标签 / 构造 / 成本四子块）与其指纹；任何工位不得自带同名参数 |
| **四个锚点指纹** | `plan` / `blueprint` / `policy` / `domain`，写入 `Ticket`；系统共八个指纹 |
| **policy_view / runtime_facts** | 调用单里口径的**具体取值** / 执行期确定且会改变结论的事实（计数、揭示状态） |
| **子调用（composed）** | 由编排层按声明预先构造的内层调用单；实现只能执行它，不能自己拼 |
| **证据等级** | 产物标注「样本内构造诊断」或「样本外可发布结论」；只有后者可用于发布 |
