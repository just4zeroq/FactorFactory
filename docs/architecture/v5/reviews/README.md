## 模块审查文档的统一结构

每份 `module-review/NN_*.md` 都含：

1. 头部（审查日期 / 依据 / 判据 / 只读声明）
2. **D1 应然**——抛开实现，这个模块该做什么（加密特化）
3. **具体例子·输入输出**——用 `venv/Scripts/python.exe` 真实运行，贴真实输入结构与输出矩阵，含失败路径错误码（非手写示意）
4. **D2 差距**——少什么/多什么/删什么/补什么，每条带 `文件:行号` + P0/P1/P2
5. **D3 业界方案**——借鉴什么/拒绝什么 + 加密理由
6. **D4 代码问题**——已确认正确逐条带行号 + 发现的问题
7. **D5 设计文档是否需更新**
8. **D6 是否需扩展 / 当前是否支持**
9. **C1–C12 相关项判定**
10. **R1–R7 影响**
11. **结论**
