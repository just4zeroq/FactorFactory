## 4. 本轮确认并修掉的缺陷

### P0-1 `inv_vol` 拿分数波动冒充资产波动
- 证据：`allocate._inv_vol_history` 原实现遍历的是 `score` 序列；而 `06-evaluation` §5.2 的定义是「按 trailing 波动倒数加权，降低**高波动标的**支配」。
- 后果：口径名不变、数值看起来正常，但含义完全不同（权重由因子离散度而非资产风险决定）。
- 修复：`allocate.inputs` 增加**可选** `price`；`_inv_vol_history(price)` 用 `r_t = p_t/p_{t-1}-1` 的 Welford 滚动方差（只用 `[0..t]`，PIT 不变）；`weighting=inv_vol` 而 `price` 缺失 → `E3003`，**不猜**。
- 印证：`tests/v5/test_v5_s4_allocate_backtest.py::test_allocate_inv_vol_weights_by_price_volatility`（低波动标的权重更大）、`::test_allocate_inv_vol_without_price_fails_closed`。

### P0-2 等权合成被量纲支配
- 证据：`combine` 原先把各候选暴露直接 `nansum/count`。暴露来自任意表达式（`close/volume` 与 z-score 差 1e4 倍），"等权"变成"按量纲加权"。
- 修复：`_cs_zscore` 逐 bar 在**标的维**标准化后再平均（常数行记 0，无效格保持 NaN）。
- 印证：`tests/v5/test_v5_s4_combine.py::test_equal_weight_standardises_before_averaging`（把 1e6 倍的候选缩回原尺度，合成分数逐位一致）。

### P1-1 `dropped_bars.by_reason` 双计
- 证据：`min_members` 与 `insufficient_members` 同时写 `n_min_members`，`count=1` 时 `by_reason` 之和为 2，违反 `14-test-strategy.md` 的「`by_reason` 之和 = `count`」。
- 修复：只保留 s0/04 §3.9 的三个标准码，互斥且求和等于 `count`；`inv_vol` 历史不足的回退行不是丢弃行，移到 `dropped_bars.fallback.inv_vol_history_short`。

### P1-2 把「未知毛收益」写成 0 再减成本
- 证据：首版 `_run_single_factor_costs` 无条件 `cost_adj_return = float(metrics.get("gross_return", 0.0)) - cost`。live 实测 5 条候选的 `gross_return` 全为 `None`，结果被写成 `-2.5e-05 ~ -3.8e-04`。
- 后果：Verdict 的 `cost_fail` 会否掉一批**根本没算出毛收益**的候选，「证据不足」被伪装成「净收益为负」。
- 修复：只有在 `gross_return` 存在时才换算 `cost_adj_return`；成本信息仍写 `cost_attribution`（`method_id`、逐期摊还、`net_ref`）。

### P1-3 Portfolio 尾链的输入对齐
- 证据：Boundary 按整段供给给掩码（95 行），Panel 会按对齐规则裁行；直接拿掩码乘分数会把错位行当同一时点。
- 修复：`_align_to_panel` 按 Panel 时间轴 `searchsorted` 精确重排，时间轴不是子集即 `E3003`（不猜、不截断）。

### P2-1 `np.mean(bt_out.get("turnover") or 0.0)`
- 证据：`turnover` 是逐 bar 数组，`or` 触发 `ValueError: truth value of an array is ambiguous`，被 executor 兜成 `E3004 未预期异常`，错误码误导成「未实现」。
- 修复：显式判 `None` 再取均值。

### P2-2 可选输入缺失被当成必填失败
- 证据：`price` 变成可选输入后，若桥内解析不到会直接 `E3003`，即使口径是 `equal` 根本不需要它。
- 修复：按 `required` 标记区分——必填照旧抛，可选落 `None` 占位（与 `funding` 的中间占位语义一致）。

## 6. 尚未闭合的 S4 退出门槛

1. **AC34（资金费周期无关性）没有测试**。当前实现按 bar 级 `prev_w × funding` 求和，天然与结算网格无关；但「1h/4h 两份事件表聚合到同一 bar 金额相等」这一步在供给层（S2 采集/聚合），需要一条跨层测试才能真正判 AC34。
2. **AC33 的数值判据不可执行**。设计上只允许 `calendar_365`（I33），所以「与 252 的比值」这条判据已失去对象；若要保留可判定性，应在 `10-crypto-fit.md` 的 AC33 上写明「252 在校验期即拒绝，故比值判据作废」，否则验收时会被当成未过。
3. **bar 频率假设硬编码为 1 天**。`backtest_engine.py:49/92` 用 `_BASE_TS + i*_DAY` 造时间轴，`sharpe` 乘 `sqrt(365)`。当前 V5 供给只有 1d，故正确；一旦接 1h/4h 供给，年化与 `funding` 的 bar 折算会同时错。建议的修法（未实施）：`backtest` 增加可选 `times` 输入（或由 supply 注入 `bars_per_year`），年化系数由 bar 间距推出，`annualisation_used` 回写实际用的年数。
4. **`turnover_series` 与成交口径不完全同源**。`turnover_series` 由**目标权重**差分算出，而成本由 ml4t **实际成交**（`fills_w`）算出；杠杆受限/部分成交时两者会分叉。S4 诊断阶段可接受，但 `06-evaluation` §5.3 要求「`turnover_series` 是成本唯一输入」，接 S7 前需要对齐（要么成本也走目标权重，要么 `turnover_series` 改由 fills 汇总）。
5. **`_fill_weights` 以初始权益折算**。长回测里权益变化会让成交权重与当期持仓权重产生偏差（成本按初始权益计价）。量级小，但属于口径缺口，接 S7 复算时需要决定用当期权益还是初始权益。
