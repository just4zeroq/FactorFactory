## 2. 独立审查：5 个 P0

review 由只读子代理执行，每条都在 `./venv/Scripts/python.exe` 下实测复现；主审复核后逐条修。

### P0-1 `forward_return` 分子分母颠倒（主审自查发现，先于 review）

`out[:T-end] = price[start:T-horizon] / price[end:] - 1` 算的是「过去 ÷ 未来」。
数值看着合理，方向整体相反——IC 符号随之翻转，`Verdict` 的 t 值与组合持仓方向相反，
两边都不报错。修正为 `price[end:] / price[start:T-horizon] - 1`，并加
`test_forward_return_direction_is_future_over_past`（下跌的未来必须给负收益）。

### P0-2 `min_coverage` 用全期覆盖率判定逐格可用性 = 前视

`covered = (alive & run).sum() / run_bars` 让一根 bar 能不能用由它**之后**的缺口决定：
只在后半段出现过的标的，前半段本有效的格被整列抹掉。且这些格被标成 `missing_data`，
而该码的判据是「该格为 NaN」——格不是 NaN，码是假的。

修法：改成 trailing 覆盖率（`trailing_coverage`，分母是实际回看根数），逐格判；
低于阈值的格退出 top-k 与分层（`tiers=-1`）。

顺带修掉一个连带缺陷：用 `trailing_mean(valid.astype(float))` 算覆盖率，分母是
「窗口内有效计数」，稀疏数据里孤立样本的覆盖率恒为 1.0，门禁永不触发。必须用
「本该有几根」作分母。

### P0-3 `causal_probe` 恒通过，且 `checks` 四项 `passed` 全硬编码 `True`

原探针「打乱未来值、看历史统计是否变化」在纯数组上恒通过——它测的是
`trailing_mean` 自己（已实现为因果的算子），不是数据；上游 `shift(-1)` 过的数组照样通过。
`mode=none` 时仍报 `P4 passed=true`，是把「未执行」写成「已通过」。

修法：`causal_probe` 改为**检查强度**开关，`strict` 跑逐位比对（面板必须与流在保留行上
逐字节一致）+ 时间连续性（相邻行间隔不得超正常步长）；`checks` 只列实际执行的检查，
`passed` 由结果计算，`violations` 非空即整步失败。`mode=none` 只报 P1–P3。

### P0-4 `mine` 与 `oos` 之间允许洞 → 标签跨洞

`boundary` 只拒绝 holdout 与 run **相交**，允许中间跳过一段。`align` 把 `mine ∪ oos`
按索引拼接，洞两侧在数组里相邻，而 `forward_return` / `trailing_mean` / `rolling_beta`
全按「相邻一根」解释：`mine` 最后一根的标签直接用上 `oos` 的价格。实测
`mine=01-05..01-10`、`holdout=01-11..01-20`、`oos=01-21..01-25` 时，`mine` 段 6 行的
标签全部引用 holdout 之后的价格。

修法：`boundary` 拒绝 `mine_hi != oos_lo`（`E4002`），被跳过的区间只能声明为 holdout；
`align` 再加一道 `P5 continuity` 防线，防手工构造的 `Scope` 绕过。

### P0-5 标签窗口触及保留区 = 泄漏（主审在修 P0-4 时发现）

`usable` 排除了 holdout 那几行，但没排除**窗口触及 holdout 的行**：`holdout=(20,26)`、
`horizon=3`、`entry=next_close` 时，`t=18` 的标签用 `close[22]`——那根在保留区里。

修法：用累积和算出「`[t+1, t+offset+horizon]` 是否含保留区时点」，触及即不可用；
`dropped_bars.by_reason` 增 `holdout_leak`（四类互斥）。

### P0-6 `nw_adjusted` 静默降级为「不做处理」

`else: sample = usable` 把 `nw_adjusted` 变成「保留全部重叠样本」，但输出里没有任何
字段记录用了哪种策略。下游看到 33 个「独立观测」会算朴素标准误，显著性被系统性高估。

裁决：`nw_adjusted` **不改样本**是正确的（截断阶数属于判据口径，标签层无权替 Evidence
决定），但必须回写 `overlap_policy_used`；未声明时为 `"none"`。文档同步写明这条分工。

## 4. 文档对齐（6 处，`s0/04` + `s0/05`）

1. **§3.2 补 `time_axis` 的字符串格式与 `axis_resolved` 结构**：`<YYYY-MM-DD>..<YYYY-MM-DD>`
   闭区间 → 半开索引区间；`start/end` 是时间轴上的实际时戳（闭区间首末），不是索引；
   `holdout=reserved` 不解析，按 `mine ∪ oos` 的补集标理由码。
2. **§3.2 新增「`mine` 与 `oos` 之间不得有洞」**，并写明跨洞会怎样错。
3. **§3.2 补理由码表与优先级**：8 个码、两张掩码各自允许的码、优先级与码值**不是同一个序**
   （结构性原因先于数据质量：稳定币被标成「流动性不足」会把读者引向成交量）。
4. **§3.2 补 `min_coverage` 的语义**：回看覆盖率、分母是实际回看根数、低于阈值即退出 top-k
   与分层。这是本层唯一一处容易混进来的前视，必须写清。
5. **§3.3 重写 `causal_probe`**：从「打乱未来值」改为「检查强度」；补 P1–P5 五个编号
   （原文写「`id` 取 C1–C22 中与面板相关者」，但 C1–C22 全是编译期配置校验，没有面板项）；
   `holdout_boundary` 的 reserved 形态；`tz` / `tz_source`；`min_obs_basis`；返回行补
   `holdout_visibility`。
6. **§3.4 补 `label` 的返回与失败**：`label_ref` 与 `score_ref` 指向两个对象（毛标签 vs 分数）
   及理由；口径镜像逐项比对；`dropped_bars` 四类互斥；`overlap_policy_used` 与 `nw_adjusted`
   的责任分工。`s0/05 §3.1` 的 `dropped_bars` / `overlap_policy_used` 同步。

`params.json` 的契约改动：`boundary.outputs` 加 `reason_code_legend` / `scope`；
`align.outputs` 改 `field_manifest` 为 `list`、加 `panel` / `holdout_visibility`；
`label.outputs` 加 `dropped_bars` / `overlap_policy_used`；`read.outputs` 加 `stream`。

已知边界（不是缺陷，是排期）：

1. **`read` 仍是 S1 空壳**。`params.json` 已声明 `read.outputs.stream` 为 `opaque`，
   但 `ops/read.py` 未实现、未登记。M1 的 `FieldStream` 全部由测试手工构造，
   面板对齐还没有在真实供给版本上跑过一次。归 S3-M2（evaluate 之前必须先有 `read`）。
2. **`params` 的默认值仍在运行期兜底**（`params.get(k, default)`），而 `params.json`
   仍只有 `type/required` 两项、没有 `class/default`。这是 M0 review 已标注的延后项，
   与 `05-contracts` 的「运行期无任何默认兜底」尚未对齐。
3. **`mask_policy=static` 的分层用全期均值**（06 明文许可），但档位会流向 `allocate`；
   建议在文档里标注「仅诊断用」，暂未改。
4. `array_digest` 把 `-0.0` 与 `0.0` 当不同值，而 `contracts/digest.py` 的规范归一为 `0.0`
   —— 全系统两套 `-0.0` 约定，会让缓存无谓失效。影响面小，未改。
