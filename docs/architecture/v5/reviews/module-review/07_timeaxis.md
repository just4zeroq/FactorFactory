## D1 · 应然（抛开实现，这个模块该做什么）

Timeaxis 提供时间区间的**唯一展开实现**，消除"同一区间字面量两处解释"的隐患：

1. **两套返回、一个算法**：`day_bounds(text)` → 闭区间纳秒边界 `(起日 00:00:00Z, 止日 23:59:59.999999999Z)`（**末日最后一纳秒**，`hi = 止日 + DAY_NS - 1`）；`resolve_interval(text, times)` → 半开行区间 `[lo_row, hi_row)`，内部就是 `day_bounds` + 两次 `searchsorted`，不存在第二种算法。`read.window` 的构造方与 `boundary/label/align` 都必须用它。
2. **末日整天包含**：`hi` 取末日最后一纳秒、`searchsorted(..., side="right")`，保证止日当天所有 bar 都进区间——若用"次日零点 side=left"，止日首根会被悄悄算进下一段而两边不报错。
3. **边界向数据截断、整段落空即拒**：早于首根取 0、晚于末根取 size（"研究窗口比数据宽"是正常声明），但整段落空即 `E4002`——空区间不是"跑出空结果"，是没定义研究窗口。
4. **1900–2100 纳秒 sanity**：`check_ns` 把毫秒/微秒/秒级异常值在"窗口落空"这种间接症状之前认出来；`CALENDAR_DAYS_PER_YEAR=365` 集中此处一处定义（G8），不做成可配置旋钮。
5. **拒绝重叠/洞/reversed**：`window_for_axis` 拒 mine/oos 重叠、中间留洞、oos 未声明；`day_bounds` 拒起>止。

**加密特化**：24/7 无休市，日历年长度 365 是**定义性常量**（进 `bars_per_year` 与年化，开放成参数等于允许同一 Sharpe 两个年化口径）；每年多少根 bar 由频率决定（1d=365、1h=8760），不是这个常量。无交易日历参与边界判断。

## 具体例子 · 输入什么 / 输出什么（真实运行，非手写示意）

> 用 `venv/Scripts/python.exe` 直调 `v5.capability.timeaxis` 各函数**实测打印**。时间轴 `START=2024-01-01` + `arange(30)*DAY_NS`（01-01..01-30）。临时脚本在系统临时目录，未改仓库。

### [A] 常量（实测）

```
DAY_NS = 86400000000000    CALENDAR_DAYS_PER_YEAR = 365
NS_MIN = -2208988800000000000 (1900-01-01Z)   NS_MAX = 4102444800000000000 (2100-01-01Z)
```

### [B] `day_bounds`：末日最后一纳秒（实测）

```
day_bounds("2024-01-05..2024-01-10") = (1704412800000000000, 1704931199999999999)
lo 对应 UTC  = 2024-01-05T00:00:00.000000000
hi 对应 UTC  = 2024-01-10T23:59:59.999999999
hi+1         = 2024-01-11T00:00:00.000000000     ← 证明 hi 是末日最后一纳秒
lo == parse_day("2024-01-05")          : True
hi == parse_day("2024-01-10")+DAY_NS-1 : True
```
→ 止日 01-10 整天被包含；`hi+1` 恰为次日零点，验证 `side=right` 语义。

### [C] `resolve_interval`：半开行区间（实测）

```
resolve_interval("2024-01-05..2024-01-10", times) = (4, 10)
  对应时点 times[4]=1704412800000000000(01-05) … times[9]=1704844800000000000(01-10)
超宽区间 "2023-12-01..2025-01-01" → (0, 30)      ← 边界向数据截断，全量
末日单日 "2024-01-30..2024-01-30" → (29, 30)      ← 含末根
```

### [D] `window_for_axis`：read.window 闭区间纳秒（实测）

```
axis = {mine:"2024-01-05..2024-01-20", oos:"2024-01-21..2024-01-25", holdout:"reserved"}
window_for_axis(axis) = {'start':1704412800000000000, 'end':1706227199999999999}
  start UTC = 2024-01-05T00:00:00.000000000
  end   UTC = 2024-01-25T23:59:59.999999999   ← 末日最后一纳秒
  end == parse_day("2024-01-25")+DAY_NS-1 : True
oos="" + oos_optional=True → {'start':..., 'end':1705795199999999999}（end=mine 止日 01-20）
```
→ 保证"读几行"与"boundary 认为哪几行属于研究对象"由同一函数决定（`:130-165`）。

### [E] 失败输入 → 错误输出（fail-closed，实测）

| 非法输入 | 输出（错误码 + 真实消息） |
|---|---|
| `day_bounds("2024-01-10..2024-01-05")`（起>止） | `E4002` "区间 '2024-01-10..2024-01-05' 的起始日晚于终止日" |
| `day_bounds("2024-01-05")`（无 `..`） | `E4002` "区间必须是 '<起>..<止>'，得到 '2024-01-05'" |
| `parse_day(20240105)`（非文本） | `E4002` "t 必须是 'YYYY-MM-DD' 文本，得到 int" |
| `check_ns(5e18)`（>2100） | `E4002` "t=5000000000000000000 不在 1900–2100 的纳秒区间内" |
| `check_ns(-3e18)`（<1900） | `E4002` "t=-3000000000000000000 不在 1900–2100 的纳秒区间内" |
| `resolve_interval("2030-01-01..2030-01-05", times)`（落空） | `E4002` "区间 [1893456000000000000, 1893887999999999999] 在数据上没有落到任何时点" |
| `rows_for_bounds(..., 空时间轴)` | `E4002` "区间 [...] 在数据上没有落到任何时点" |
| `window_for_axis(mine..01-10, oos..01-15 起)`（中间洞） | `E4002` "mine 与 oos 之间不得有洞" |
| `window_for_axis({mine:...})`（oos 未声明） | `E4002` "t.oos 未声明" |

### [F] sanity 边界的真相（实测，见 D2 T-2）

```
check_ns(1700000000000000)  [2024 的微秒值当 ns] → OK，原样返回（落在 1970-01-20，仍在 1900–2100 区间内）
check_ns(1700000000000)     [2024 的毫秒值当 ns] → OK，原样返回（1970-01-01）
check_ns(5e18)/check_ns(-3e18) → E4002（真超区间）
```
→ 1900–2100 sanity 只拦"极端值"，对 1970 后的 ms/us 整数值不敏感；端到端靠 `read` 的 RFC3339 校验 + coverage 拦截（见 03_read R-4）。

## D2 · 差距（少什么 / 多什么 / 删什么 / 补什么）

| # | 差距 | 级别 | 证据 | 判断 |
|---|---|---|---|---|
| T-1 | **`parse_day` 宽松接受非严格 YYYY-MM-DD**：实测 `"2024-01"`→2024-01-01、`"2024"`→2024-01-01、`"2024-01-05T00:00:00"`→2024-01-05（均 OK），只有 `"2024-1-5"`/`"2024-13-01"` 被拒。docstring 说"YYYY-MM-DD"，但 numpy `datetime64(text,"ns")` 接受部分日期/带时间。一个写错的 `"2024"` 会静默变成 2024-01-01。 | P2（输入校验） | `timeaxis.py:61-76`（parse_day）；实测 | **需确认意图**：区间字面量来自 plan（18-plan-schema），若编译器已用 schema 卡严格格式则端到端无碍；但 timeaxis 自身 docstring 强于行为。建议加正则 `^\d{4}-\d{2}-\d{2}$` 预校验，属防御性加固，非本轮 bug。 |
| T-2 | **1900–2100 sanity 对 ms/us 整数不敏感**（实测 F）：2024 的微秒值 `1.7e15` / 毫秒值 `1.7e12` 当纳秒落在 1970、仍在区间内，不被 `check_ns` 拒。docstring"毫秒/微秒/秒会落在区间之外"对 1970 后日期不成立。 | P2（说明/纵深防御） | `timeaxis.py:41-58`；实测 F；`read.py` R-4 | **需确认意图**：端到端 `run()` 路径已由 `read` 的 RFC3339 参数校验闭合（裸 int → E1004），不构成前视/静默错误；但措辞需改。与 03_read R-4 同源，建议统一改文档措辞。 |

**多了什么**：无冗余。`day_bounds` 与 `resolve_interval` 分层（纳秒边界 vs 行区间）是刻意的——前者给 window 构造方，后者给 boundary/label/align，共用同一 `day_bounds` 内核，正是"唯一实现"的价值。

## D3 · 业界方案（借鉴什么 / 拒绝什么）

| 方案 | 裁决 | 加密理由 / 证据 |
|---|---|---|
| 单一区间解析器（`day_bounds` 内核 + 两处调用） | 采纳 | 两处各写一份会有 2×3 种边界组合、且不一致时无检查点报错（文件头 L3-11）；唯一实现消除分叉 |
| 末日最后一纳秒 + `side="right"` | 采纳 | "闭区间的日含不含末日"是最易错处；`hi=止日+DAY_NS-1` 保证末日整天进（`:79-99`） |
| `searchsorted(side="left"/"right")` 半开行区间 | 采纳 | 精确定义边界归属、可复现（`:110-111`） |
| 交易日历 / `pandas-market-calendars` | **拒绝** | 24/7 无休市；日历年 365 是定义常量、不开放为旋钮（`:35-40`，C1/G8） |
| "窗口落空返回空结果" | **拒绝** | 整段落空 `E4002`——空区间没定义研究窗口、会一路静默传播（`:114-120`） |
| 为补尾部标签越界读到 holdout | **拒绝** | 多读一天就是泄漏，且以"标签更完整"形态出现（`:142-145`）；缺口由组合层 embargo 显式声明 |

## D4 · 代码问题（bug / 静默成功 / 口径漂移）

**已确认正确（逐条带证据）**：
1. **唯一实现**：`resolve_interval` 内部仅 `day_bounds + rows_for_bounds`（`:124-127`），无第二算法；boundary 测试 `test_time_axis_uses_the_single_timeaxis_implementation` 钉住。
2. **末日最后一纳秒**：`hi = parse_day(止日)+DAY_NS-1`（`:93-94`），实测 hi+1=次日零点，`window_for_axis.end` 同为末日最后一纳秒（`:139,151`）。
3. **边界向数据截断 + 落空拒绝**：`rows_for_bounds` 用 `searchsorted` + clamp（`:109-113`），落空 `E4002`（`:114-120`），实测超宽截断为全量、远段落空拒。
4. **1900–2100 sanity**：`check_ns`（`:49-58`），实测 ±极端值 E4002（边界真相见 T-2/F）。
5. **365 常量集中**：`:35-40`，不配置化（G8/C1）。
6. **拒绝重叠/洞/reversed/未声明 oos**：`window_for_axis`（`:150-164`）+ `day_bounds` 起>止（`:95-98`），实测四类拒。
7. **window 不越界读到 holdout**：`:142-145` 注释与实现（end 取 oos 止日，不补尾部），防"多读一天泄漏"。
8. **无 pyarrow/pathlib/os/io/duckdb 依赖**：只 numpy + 错误类型（`:22-24,27-33`），符合 AC31 静态扫描。

**发现的问题**：
- 无 P0/P1 级代码 bug。T-1（parse_day 宽松）、T-2（sanity 措辞）、T-3（分工说明）均为 P2。测试覆盖（`test_v5_boundary_align.py:127-145` + 本次真跑的 9 类失败路径）充分。
