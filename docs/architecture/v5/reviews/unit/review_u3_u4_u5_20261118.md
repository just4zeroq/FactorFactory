### 1.1 D1 应然（理想态规格）

- **输入**：外部交易所/V4 快照的四类数据集（ohlcv / funding / open_interest / basis）；研究员声明的 `(dataset, exchange, market, symbols, timeframe)`。
- **输出**：一组不可变 parquet；读取时现算的 `Dataset`（checksum / version / coverage / interval_ns / gaps / acquired_at / symbols / per_symbol_bounds）与内存 `Pin`。
- **不变量**：① 一标的一文件；② `timestamp` UTC aware；③ 同 `(symbol,timestamp)` 旧值永不覆盖；④ 写盘只经同盘 tmp + `os.replace`；⑤ 身份由内容决定，无 manifest/版本目录/别名表；⑥ 事实层不可变、可重建；⑦ `version = checksum[:16]`。
- **禁止项**：静默改写历史；用文件名推事件流频率；用 exchange 推 market；spot 目录出现 funding；自动缩窗；无 manifest 时虚构 manifest 路径。
- **边界**：采集/存储是独立写者，不属于八工位，不写执行状态；`market` 独立于 `exchange`。

### 1.3 D3 业界方案

| 方案 | 采纳/拒绝 | 加密理由 |
|---|---|---|
| Parquet/Arrow 列存 + 固定序列化参数 | **采纳**（`objects.py:33-34,129-135`） | 跨 pyarrow 版本字节一致，否则 blueprint_digest 随依赖漂移 |
| content-addressed storage（git object 模型） | **采纳**（`objects.py:81-91`） | 同名即同内容，事实层不可变 |
| event sourcing append-only log | **采纳**（`ledger.py`、`catalog.py`、`upstream/store.py:342-401`） | 历史值不覆盖是加密数据红线（V4 `keep="last"` 是反面教材） |
| DuckDB 查询面 + reconcile 重建 | **采纳**（`index.py`） | 索引不是真相；删库可重建 |
| manifest + 版本目录树 + 别名表（S2 旧协议） | **拒绝**（`19-supply.md:176-189` 已删 8 文件） | 单机批量研究不需要多写者协议；身份现算足够 |
| 原地 `to_feather` / `keep="last"`（V4） | **拒绝** | 静默改写历史，过去结论无法解释 |
| **事件流自适应间隔判定**（如按 P95 间隔或 event-count 窗口） | **建议采纳** | 当前 3× 中位数对「1h→8h 结算切换」无效；这是加密特有，股票无此问题 |
