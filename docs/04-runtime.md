# 04 · 运行时

> 本篇定义跑之前有什么、跑的时候东西放在哪、谁能写，以及为什么数据下载必须在流水线之外。

---

## 1. 运行时的三个世界

| 世界 | 存在时点 | 内容 | 写入权限 |
|---|---|---|---|
| **静态章程** | 运行前 | 基线清单、研究计划、schema、名字目录、契约版本表 | 随实现版本发布，运行期零写入 |
| **运行时环境** | 编译之后才被完整观测 | 实现/依赖版本、时钟、随机源、资源上限、凭据引用名 | 开执行时落盘一次 |
| **执行现场** | 一次执行期间 | 冻结方案副本、产物索引、八工位独立目录、日志、事件记录 | 只写本次执行自己的目录 |

用户看到的是「运行前有一份静态配置文件，运行时有一套环境」。这两者**不是配置的上下两层**：环境不是配置的第四层，不能覆盖构成性参数，也不能充当「没配就取环境默认值」的兜底。

---

## 2. 静态配置：编译，不是读一个文件

配置里有两类性质完全不同的东西：

- 一部分决定**系统在回答哪个问题**：交易哪些标的、按什么时间轴、成本怎么算、多久再平衡、什么算显著。
- 另一部分决定**系统怎么把这件事做完**：缓存、并行度、日志、产物路径、超时。

前者一旦可变，就等于换了一个实验；后者变了，结论不该有任何变化。把两者混在一张扁平参数表里，是「配置自由度悄悄变成模型选择」的起点。

因此配置模型不是「读一个 JSON」，而是**编译**：把三层意图合成一份冻结的、可校验的、可逐项追溯来源的执行方案，称为 **Blueprint**。

| 层 | 名称 | 内容 | 能否改构成性参数 | 版本 |
|---|---|---|---|---|
| 1 | **Baseline@vN** | 随实现发布的完整默认：每个模块的默认实现与参数、判据阈值、经济口径 | 只读 | 显式 `@vN` |
| 2 | **Plan** | 研究计划：只写与基线不同的项，以及口径声明（试验族、声明时间、可交易边界） | 可以，但必须已声明且冻结 | 由 `plan_digest` 锁定 |
| 3 | **Override** | 命令行临时覆盖 | **默认只接受操作性参数**；改构成性参数须显式放行并强制新建试验族 | 写入来源表 |

优先级 `Override > Plan > Baseline@vN`。基线是一份**可 diff、可随版本发布的完整清单**，不是散落在实现里的字面量；系统必须能回答「某一步的默认实现是什么」，而不需要读实现源码。

---

## 3. 编译产物与步骤

| 字段 | 说明 |
|---|---|
| `values` | 全量展开的配置树，**没有任何「运行期再取默认」的位置** |
| `origins` | 每个叶子路径的来源：`baseline@vN` / `plan` / `override` |
| `resolved` | 每个模块最终解析出的 `实现@版本` 与参数 |
| **`caliber`** | **口径块**：`execution` / `label` / `allocate` / `net` 四块，工位不得自带同名参数 |
| `plan_digest` / `blueprint_digest` / `policy_digest` / `domain_digest` | 四个意图与口径指纹，见本篇 §6 |
| `baseline_version` | `@vN` |
| `supply_pins` / `supply_digest` | 编译期固化的事实版本引用及其指纹 |
| `family_declaration` | 试验族标识与声明时间 |
| `station_order` | 固定八工位序列与各自契约版本 |
| `compiled_at` | 仅记录，不参与任何判据 |

`caliber` 是**独立于工位的一层**：它不是「某个工位的参数」，而是被标签、证据、组合、认证共同读取的口径。把成本与构造放进工位参数，就等于允许每个工位有一份；放成顶层块，才只有一份。字段与约束见 `06-evaluation.md`。

编译步骤：

1. 载入 `Baseline@vN`，得到完整配置树。
2. 按路径叠加 Plan；**未知路径立即失败**。
3. 叠加 Override；检查是否触及构成性参数，未经放行则失败。
4. 合并 `caliber` 四块；**任何工位参数里出现 `caliber` 已定义的字段立即失败**（C20）。
5. 对每个模块解析配置单里的名字；**名字不在目录中立即失败**，结果固化为 `实现@版本`。
6. 按该实现的 `param_schema` 逐项校验；**schema 之外的字段、缺必填、类型不符一律失败**，不得忽略多余字段。
7. 按各能力的 `composes` 声明解析子调用图；**未声明的组合、超过两层的嵌套立即失败**。
8. 校验参数间一致性、组合三段窗口与重叠声明、经济口径自洽（C9 / C21 / C22）。
9. 把共享数据别名解析成精确版本引用，并做只读适用性门禁。
10. 计算四个指纹、冻结成只读结构、生成来源表。

编译完成后 Blueprint 不可变，运行期任何组件拿到的都是只读视图。

## 4. 名字 + 参数与两类参数

配置单的形态极简：**每个模块一行「名字 + 参数」**。名字指向已登记的实现，参数是该实现自己的。挖掘写 `algorithm: <名字>` 加算法参数，数据写 `exchange: <名字>` 加字段清单，其余模块同理。名字空间分档与能力目录见 `01-capability.md`，算法专属的参数定义见 `02-mining-interface.md`。

| 维度 | **构成性（Constitutive）** | **操作性（Operational）** |
|---|---|---|
| 回答的问题 | 我们在研究什么 | 我们怎么把它算完 |
| 举例 | 可交易边界、成本档位、标签跨度、再平衡、试验族、搜索空间、显著性阈值 | 缓存、并行度、日志级别、产物根目录、超时、报告格式 |
| 进 `policy_digest` | 是 | 否 |
| 改动代价 | **新试验族**，旧计数不复用，下游标失效 | 无统计代价 |
| 允许扫参 | 只允许**预注册枚举**，禁止自动遍历 | 允许 |
| 单步能否覆盖 | 不能 | 可以 |

判据：如果改了这个值，同一个「显著」结论可能变成不显著，它就是构成性的。这条判据比列举字段更可靠，新字段出现时也能直接归类。

> **配置组合本身就是模型选择。** 池定义、成本档位、零分布构造、标签跨度、判据阈值，每一个都是能翻转结论的旋钮。若可自由组合，实际试验次数远大于显式候选数，而门槛只按显式候选数计算，结论被系统性高估。

## 5. 校验：全部 fail-closed

| # | 触发条件 | 处理 |
|---|---|---|
| C1 | 配置路径不存在于 schema | 拒绝编译，指出最近似合法路径 |
| C2 | 实现名不在能力目录 | 拒绝编译 |
| C3 | 参数出现 schema 之外的字段，或实现签名与接口契约不符 | 拒绝编译；多余字段不得静默忽略 |
| C4 | 类型、范围、枚举值不符 | 拒绝编译 |
| C5 | 构成性参数出现在 Override 且未放行 | 拒绝编译 |
| C6 | 构成性参数改动但试验族未声明 | 拒绝编译 |
| C7 | 严格模式未注入裁决者 | 拒绝编译并拒绝执行 |
| C8 | 默认实现指向演示/占位实现 | 拒绝编译 |
| C9 | 经济口径不自洽（例如闸门成本与回测成本不一致） | 拒绝编译 |
| C10 | 实现参数与所声明的拟合/变换阶段冲突 | 拒绝编译 |
| C11 | 共享数据别名未解析、指向完整性门禁未通过的版本，或快照缺失/校验失败 | 拒绝编译；不得自动补采 |
| C12 | 已解析版本的覆盖范围、新鲜度或末端闭合不满足本次时间轴与标的集 | 拒绝编译并提示先做维护；**只读校验，不得自动补采** |
| C13–C17 | 算法名、参数 schema、字段覆盖、算子白名单、有状态拟合约束 | 拒绝编译，逐条见 `02-mining-interface.md` §7 |
| C18 | 组合域成员口径不一致、缺可用时间，或纳入规则含表现类条件 | 拒绝编译 |
| C19 | 组合拟合窗口起点早于域内最晚可用时间 | 拒绝编译 |
| **C20** | 工位参数里出现 `caliber` 已定义的字段（跨度、入场价、成本档、年化、构造约束），或实现自行声明与 `composes` 不符的子调用 | 拒绝编译，指出该字段应写在 `caliber` 的哪一块 |
| **C21** | 组合三段窗口非法：`fit.end + embargo > eval.start`、`eval.end` 越出搜索区间、`fit` 与 `eval` 重叠 | 拒绝编译 |
| **C22** | `rebalance < horizon` 但未声明 `overlap_policy`，或 `width_policy` 缺失 | 拒绝编译 |

**没有一条规则允许「忽略并用默认值继续」**。运行期静默兜底会让记录里的配置与实际执行的配置不一致，是假成功最常见的来源。

C20 是这套设计里最值钱的一条：它把「同一口径」从一句承诺变成一次字段级比对。没有它，证据层与组合层各自写一份成本参数也能编译通过，然后「判据用便宜口径、回测用昂贵口径」会在报告里以两句互斥的结论出现。C21 与 C22 各自封住一条横截面研究的经典漏洞：用同一段数据既拟合又评估、把重叠标签当独立观测。

## 6. 指纹：八个总量，四个锚点

系统里一共八个指纹，分两组；但只有四个进入 `Ticket`，被称为**锚点**。这个区分是为了避免「说四个还是八个」的混乱。

| 组 | 指纹 | 覆盖内容 | 用途 |
|---|---|---|---|
| 意图 | `plan_digest` | 用户原始输入 | 判断两次执行是否来自同一意图 |
| | `blueprint_digest` | 展开后全量配置（含操作性参数、`caliber`、数据版本引用） | 产物缓存键的组成部分 |
| | `policy_digest` | 仅构成性参数，含 `caliber_digest` 与 `domain_digest` | **跨工位共享的口径锚点**，任何 Parcel 指纹都必须包含它 |
| | `domain_digest` | 组合域成员与各自可用时间、拟合窗口起点 | 域一变，组合与下游全部失效 |
| 物化 | `supply_digest` | 全部 pin 及校验和 | 事实版本变了 |
| | `environment_digest` | 实现与依赖版本、时钟基准、随机源、资源上限 | 跑的环境变了；**单独记录，不进产物指纹** |
| | `call_digest` | 工位与契约版本、实现与版本、参数、输入、口径取值、执行期事实、子调用 | 同一步的输入变了；**缓存键** |
| | `parcel_digest` | `call_digest` + 产物指纹 | 产物变了 |

`Ticket` 锚定四个：`plan` / `blueprint` / `policy` / `domain`。其余四个由料包自身携带或按需重算。

`supply_pins` 属于**输入事实**而不是研究口径：它进 `blueprint_digest` 与料包输入指纹链，但**不进** `policy_digest`。因此数据刷新会产生新蓝图指纹与自面板起的失效传播，却不构成新的模型自由度、不新建试验族。若冻结后的引用在运行期被重新解析为「当前最新」，同一次执行的不同工位就可能读到不同事实，属于契约违反。

`environment_digest` 同理不进产物指纹：一旦进去，换台机器或升级无关依赖就会让全部历史产物「失效」，可复现反而不可比。它的正确用法是单独记录并在重放不一致时作为第一排查对象，而不是当作失效判据。

基线升版 `vN → v(N+1)` 必须显式发生并产生新的 `policy_digest`；旧执行的冻结方案保持不变，可继续按原口径复现。升版记录需说明哪些默认值变化、是否触及构成性参数；触及即等同新试验族。

## 7. `flow explain`：让「没配置走默认」可见

`flow explain --plan ...` 只编译、不执行，输出：工位序列与契约版本、逐叶子路径的最终值与来源、参与 `policy_digest` 的全部字段、四个锚点指纹与基线版本、`caliber` 四块的最终取值、试验族与种子、**逐条 C1–C22 的通过/失败**、每个 pin 的采集时间与覆盖范围。

用户不需要读实现源码或猜测，就能回答「我到底跑了什么」。

## 8. 运行时环境：Envelope

运行时环境 ≠ 运行期参数。缓存开关、并行度、日志级别属于 Blueprint 的操作性参数；实现与依赖版本、运行环境标识、时区与时钟基准、随机源、资源上限、可用设备、数据根解析结果、凭据所在位置，是编译之后才被完整观测到的**运行时环境**。

| 面 | 内容 | 落盘 | 进指纹 |
|---|---|---|---|
| 可记录面 | 实现与依赖版本、环境标识、时钟基准、随机源状态、资源上限、数据根、可用设备 | 是，生成 `environment_digest` | 进可复现清单 |
| 凭据面 | 外部访问凭据 | **只存引用名**（环境变量名或密钥库别名） | 否 |

三条禁令：

1. **环境不得改变口径**：不是配置的第四层，不能覆盖构成性参数，不能当默认兜底。
2. **凭据值绝不出现**在方案、料包、日志、指纹、报告任何一处；取值失败必须显式失败。
3. **环境差异必须可见**：同一冻结方案、同一种子两次执行若产物不一致，第一排查对象就是环境快照。它不进 `policy_digest`，但必须进可复现清单。

## 9. 四个存储区

| 区 | 名称 | 内容 | 生命周期 | 谁可写 | 运行期写入 | 跨执行共用 |
|---|---|---|---|---|---|---|
| **W1** | **Charter**（静态章程） | 基线清单、计划、schema、名字目录、契约版本表 | 随版本发布，只读 | 版本发布者 | **禁止** | 是 |
| **W2** | **Depot**（共享仓） | 事实资产、可重建派生物、全局账本 | 长期保留，只追加新版本 | 专门的维护动作 | **禁止**（工位只读） | 是 |
| **W3** | **Ticket**（执行区） | 冻结方案副本、环境快照、产物索引、八工位目录、事件记录 | 一次执行；归档后只读 | 编排层与该执行 | 允许，限定本执行 | 否 |
| **W4** | **Scratch**（暂存区） | 临时文件、失败半成品、日志缓冲 | 随时可清 | 任何执行 | 允许 | 否 |

归属判据（按顺序问，先命中先归）：表达意图或默认 → W1；外部事实且不可重建 → W2；能确定性重算 → W2 派生物或 W4；属于某次执行 → W3；丢了不影响复现 → W4。

**「跨执行可读」不等于「跨口径可读」**：共享仓里的东西可被任何执行读，但引用它的料包指纹必须包含版本，否则共享就变成绕过口径锚点的暗道。

共享仓三类资产，清理策略必须分开：

| 类 | 定义 | 能否重建 | 删除策略 |
|---|---|---|---|
| **Seed** 事实种子 | 外部采集的原始事实：行情快照、存续事实表、人工标注 | 否 | 默认不删；删前确认无任何执行引用 |
| **Derived** 派生物 | 由种子与冻结方案确定性重算出的中间结果 | 是 | 可按配额清理，不影响复现 |
| **Register** 全局登记 | 试验计数、一次性事件记录、已发布结论 | 否，是状态不是计算 | 不删、不改、不清零 |

Register 里的已发布因子必须逐成员携带：标识与表达式版本、血缘、口径摘要、试验族、**可用时间**（首次通过裁决、可被使用的时间）、裁决证据引用、退役状态。它是状态登记，不是可直接消费的组合输入。

## 10. 共享事实：不可变版本与 pin

先拆开一个词：「下载的交易所数据全局复用」有双关。

| 理解 | 后果 |
|---|---|
| **复用同一个可变路径** | 数据一刷新，历史执行读到的就不再是当时那份事实，旧结论被静默改写，且没有记录能说明它原本基于什么 |
| **复用同一份字节** | 采集产出不可变的新版本，执行在编译期把「当前版本」固化成精确引用，运行期只读该引用 |

只承认第二种。**跨执行共享的前提是不可变与精确引用，不是共享一个可变位置**；「最新」只能是一个在编译期被解析掉的别名。

一个 Seed 版本不是「文件名 + 修改时间」，而是不可变快照：目录名取内容摘要，附清单（版本、来源与采集时间、覆盖区间与标的集、校验和与缺失区间、时间末端完整性标记、schema 版本、血缘、采集侧门禁结果）。门禁未通过的版本可保留，但不得被别名指向。

| 对象 | 定义 | 作用 |
|---|---|---|
| `supply_pins` | 每个数据集最终解析出的精确版本引用 | 冻结后运行期不得再解析别名 |
| `supply_digest` | 全部 pin 及校验和的指纹 | 进入供料相关工位的输入指纹链 |
| **SupplyRef** | 编译期生成的一等输入引用，不是任何工位的产物 | 让共享事实进入指纹链，而不必伪装成某工位的输出 |

执行区料包只保存 `seed_ref = (dataset, version, checksum)`，**不把原始事实复制进执行目录**：一旦拷贝就出现第二副本，副本被就地改动时不受共享仓的不可变性保护。例外是可复现清单，它必须列全所有 pin。

## 11. 供给维护链在流水线之外

> **判据只有一句**：流水线只做「事实 → 结论」的确定性变换；任何「外部世界 → 事实」的动作都在流水线之外。

按这条判据，边界事实表、人工标注、公告抓取都属于维护链，哪怕没有网络下载；反过来，由已有事实确定性派生的面板与标签属于流水线内部，即使计算量很大。分界线是**是否产生新的外部事实**，不是有没有 IO。

四条理由：

1. **因果方向**：工位契约是「给定冻结输入，确定性算出产物」，下载产出的却是**输入本身**。让流水线自己生产输入，编译期就无从固化版本，只能写「最新」，同一次执行的不同工位可能读到不同版本。改称「第零工位」也救不了：它有外部副作用、不可重复、依赖网络时点，本质是事件。
2. **失败模式不同**：计算失败应显式失败、重跑确定；采集失败是限流、超时、部分成功、上游修订、断点续传，且「成功」必须以落盘校验为准。塞进同一状态机，会给所有工位引入用不上的外部 IO 重试语义，还会把「计数加一但没落盘」记成 `done`。
3. **统计纪律**：若每次整体跑都顺手刷新，「刷新到最新」与「重跑搜索」被永久绑定。新增时间单位本身就改变样本，刷新后反复重跑等于用新样本免费重试，计数却不会增加。
4. **单写者**：共享仓被所有执行读；若每次执行都能写，必然出现并发多写、半成品、别名指向不完整数据。

「之外」不等于失控。写入必须：发生在编译之前；同一数据集同时只有一个写者（租约或锁）；原子发布（暂存 → 校验 → 门禁 → 登记新版本 → 最后移动别名）；维护日志独立存档；**单步执行绝不触发**。

两道只读门禁不能合并：

| 门禁 | 归属 | 判什么 | 失败处理 |
|---|---|---|---|
| **A · 完整性** | 采集侧 | 覆盖区间、标的集、校验和、末端闭合、上游修订 | 版本可保留但**不得发布**，别名不移动 |

> **已被 `19-supply.md` 取代**：现在的形态是「采集直接落 parquet、无暂存/版本/别名」，
> 门禁 A 的七项拆成「读取时五项」（`store.read_dataset`）+「路径/间隔校验」。门禁 B
> 保留，`supply_meta` 由 `store` 从路径与数据现算，不读 manifest。下表与下段的
> 「原子发布 / 移动别名」作为历史描述保留，不再是实现。
| **B · 适用性** | 编译侧（只读） | 该版本是否满足本次时间轴、标的集、新鲜度、末端闭合 | **FATAL 且不创建执行**，提示先做维护，**绝不自动补采** |

三个职责不是三套系统：供给维护链（采集 → 门禁 A → 原子发布 → 移动别名，不产生执行）／外层调度（按序串联「维护 → 编译 → 执行」，保证「每次都用最新事实」的纪律，不产生执行）／研究流水线（门禁 B → 固化 pin → 八工位 → 归档，产生执行）。外层调度可以做成一个组合命令或定时任务，但维护动作仍不进状态机、不写执行记录、不参与成败判定。

| 独立的代价 | 缓解 |
|---|---|
| 多一步、容易忘 | 门禁 B 强制；`explain` 显示采集时间与覆盖范围 |
| 两套日志 | pin 作为关联键，执行记录可反查维护日志 |
| 版本累积 | 事实种子默认永久保留，删前检查归档引用 |
| 旧执行复现依赖旧版本 | 冻结 pin + 可复现清单 |

明确禁止：工位内下载、编译遇缺失自动补采、单步重放触发刷新、运行期解析别名、把维护动作的成功写进执行成败。**允许**的是前置只读检查与组合命令。

## 12. 目录形态与每步独立目录

```
Charter/                         只读
  baselines/vN/  plans/  schemas/  catalog/

Depot/
  seeds/<feed>/<dataset>/<version>/      不可变快照 + 清单 + 校验和
  pins/<dataset>                         别名，只存引用
  derived/<digest>/                      派生物，可重建、可回收
  registers/                             只追加的全局登记
  upkeep/                                维护日志、租约、锁、暂存区

Ticket/<ticket_id>/
  charter.json                           冻结方案副本 + 来源表 + 三指纹 + pins
  environment.json                       环境快照 + environment_digest
  index.json                             产物索引、状态机、失效标记
  trace.jsonl                            每工位一条结构化记录
  ledger.jsonl                           本执行相关事件（只追加）
  stations/<Station>/                    八步各一份
  steps/<seq>-<Station>-<hash>/                  单步观察产物，隔离
  report/                                认证报告、可复现清单

Scratch/                                 可随时清空
```

路径是逻辑分区，不规定物理介质；读写权限与生命周期语义不随位置改变。

运行时每个阶段有且只有一个独立目录，内容固定四类：

| 项 | 内容 | 约束 |
|---|---|---|
| `parcel.json` | 产物引用、指纹、血缘、证据、来源、状态、耗时 | 不可变；修改等于产出新料包 |
| `payload/` | 该工位产出的实际数据 | 只写一次 |
| `log/` | 该工位运行日志 | 与产物同目录、绑定同一料包指纹 |
| `diagnostics/` | 中间量、诊断图、被拒样本 | 不影响正式产物 |

**日志与产物必须同目录同指纹**：日志散在统一大文件里，当某个料包被标失效时无法一并判断它的日志是否还可信。

三条日志流：工位日志（工位目录，键为 `ticket / station / parcel_digest`）、执行记录（Ticket 根层，键为 `ticket / station / seq`）、维护日志（共享仓维护区，键为 `version / dataset`，**不属于任何执行**）。三流可互相反查，但归属不能串。

单步产物写 `steps/<seq>-<Station>-<hash>/`，标 `origin=step`，复用四件套但不覆盖正式目录、不推进状态机、不写事件账本、不改共享仓；若读共享事实，仍按冻结 pin 读同一份不可变版本。

## 13. 时间剖面

| 时点 | 动作 | W1 | W2 | W3 | W4 |
|---|---|---|---|---|---|
| T0 | 前置维护：采集、校验、原子发布、移动别名 | 读 | **写（唯一入口）** | — | 写 |
| T1 | 编译：三层合并、名字解析、别名固化为 pin、算指纹 | 读 | 读别名与清单 | — | — |
| T2 | 编译失败 | — | — | **不创建执行** | 清理 |
| T3 | 开执行：写冻结方案副本、环境快照、初始索引 | — | 读 | 写 | — |
| T4 | 八工位顺序执行 | — | **只读** pin | 各写自己的工位目录 | 写 |
| T5 | 单步观察 | — | 只读 pin | 写 `steps/` | 写 |
| T6 | 归档：报告、可复现清单、转只读 | — | 读 | 写后冻结 | 清理 |

关键在 T1 与 T4 的分离：**编译之后，共享仓对执行器就是只读的**。任何在 T4 想写共享仓的行为都是契约违反，不是优化。

**复现的定义**：给定归档执行的冻结方案副本、环境快照、全部 pin 与共享仓中对应版本，能在全新进程中重建出逐工位一致的产物。定义里**不包含**「当前最新数据」——那已经属于另一次执行。

## 14. 反模式

| 反模式 | 为什么危险 |
|---|---|
| 运行期 `get(key, default)` 兜底 | 配置拼错 → 静默换实现 → 结论不可复现 |
| 捕获配置异常后继续跑 | 把错误变成「看起来成功」 |
| 忽略未知配置键 | 用户以为改了口径，实际没改 |
| 自由遍历构成性参数 | 隐式模型选择，试验预算失真 |
| 用当前时点的全期统计生成默认值 | 默认值本身携带前视信息 |
| 让单步重新合并三层配置 | 同一次执行出现两个口径 |
| 所有执行读同一个可变数据路径 | 数据刷新静默改写历史结论 |
| 运行期解析 `latest` | 同一次执行的不同工位可能读到不同版本 |
| 编译遇缺失数据自动补采 | 编译期产生副作用，版本在编译中途变化 |
| 把原始事实复制进执行目录 | 出现不受不可变性保护的第二副本 |
| 凭据值写进日志或料包 | 泄露，产物无法安全归档 |
| 把 Seed 与 Derived 用同一套清理策略 | 误删不可重建的历史事实 |
| 日志集中在一个大文件，与产物分离 | 料包失效时无法判断日志可信度 |
| 维护动作的成功写进执行成败 | 归属串线，执行记录无法独立解释 |
