## D1 · 应然（抛开实现，这个模块该做什么）

`exit_codes.py` 定义 `flow` 命令的**唯一进程退出码枚举**。五个码语义互不重叠，关键在于 `3`（契约违反）与 `1`（执行失败）必须分开——合并后线上排查退化成猜。它该做的只有一件事：提供 `ExitCode(IntEnum)` 五个值（源码:15-31）：

| 码 | 枚举 | 语义 | 对应错误层 |
|---|---|---|---|
| 0 | `OK` | 成功 | — |
| 1 | `EXECUTION` | 执行失败或存储失败 | E3xxx / E5xxx |
| 2 | `USAGE` | 用法或编译错误，用户改输入即可 | E1xxx |
| 3 | `CONTRACT` | 契约违反，按 bug 处理，fail-closed | E2xxx |
| 4 | `SUPPLY` | 供给失败，事实层不可用/不适用 | E4xxx |

**三条硬约束**：
1. **没有"成功但有警告"的码**（源码:6-7）：警告只进结构化记录，不改退出码，也不能让本应失败的执行返回 0（V4 假成功就是这么来的）。
2. **`3`≠`1`**：3 = "代码写错了"（系统不变量破坏）；1 = "输入或环境有问题"（执行没成功）。这是用户必查点。
3. **存储失败归 1**：E5xxx（storage）映射到 EXECUTION 而非独立码——五个码没有为 IO 单列。

**加密意义**：供给失败独立成码 4（现货无 funding、末端未闭合 E4003）——24/7 数据链断供不会被误报成"用法错误"或"执行失败"，运维按码分流处置（15-operations §4）。

### 例 1 · 五码枚举值（源码定义 + 实测映射）

```
ExitCode.OK         = 0
ExitCode.EXECUTION  = 1
ExitCode.USAGE      = 2
ExitCode.CONTRACT   = 3
ExitCode.SUPPLY     = 4
```

### 例 2 · 错误码 → 退出码映射（实测，验证 3≠1 分离）

```
E1001(用法)   -> (usage,    2)
E2002(契约)   -> (contract, 3)   # 指纹 NaN/坏路径
E3001(执行)   -> (execution,1)   # 上游产物缺失
E4002(供给)   -> (supply,   4)   # 覆盖区间不满足
E5001(存储)   -> (storage,  1)   # 存储失败归执行码 1
```

**逐条解读**：
- **E2002→3 vs E3001→1（用户必查点）**：同为失败，契约违反（指纹输入非法=代码/口径被污染）走 3，执行失败（上游产物缺失=环境/顺序问题）走 1。两者严格区分，排查路径完全不同。
- **E5001→1**：磁盘满/权限不足属存储层，但退出码是 1（EXECUTION），不单列——符合"五个码"设计。
- `IntEnum` 可直接当 int 用（`int(exit_code_for('E2002')) == 3`），供 CLI 进程退出。

### 例 3 · OK=0 语义（无"带警告成功"）

源码:6-7 明确："**没有 0 以外的成功但有警告**"。任何 `Error`（包括 retryable 的）都必须向上传播（`errors.py` 硬规则一），不存在"记日志后返回 0"的路径。`15-operations.md` I32 要求 `ok`（渲染层）与 `exit_code` 一致，不一致按契约违反处理。
