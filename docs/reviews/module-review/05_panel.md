## D1 · 应然（抛开实现，这个模块该做什么）

Panel 是值对象：`(T,N)` 逐字段数组 + UTC 时间索引 + 标的清单 + 可选保留区。它不读盘、不产结论，只做"构造即校验"的可信容器。三条硬约束：

1. **时间索引严格递增无重复**（`E4007`）：重复时间戳让"同一时点两次观测"变成两个独立样本，标准误被低估——最早出现、最难发现的伪显著来源。
2. **缺失用 NaN、不静默填充**：填充把"缺席"变"某个值"，截面排序随即把它当中间值。
3. **保留区取值不得进面板**：面板是"可看的数据"，保留区混进来则后面所有"没看过保留区"的声明都失去依据。

另外：`holdout` 是**半开行区间**`[start,end)`，切片部分重叠时按交集裁剪（不是整体丢弃，否则切后那段的"没看过保留区"声明失效）；`digest()` 是内容身份，必须含时间索引/标的序/逐字段字节/`holdout`——两个"内容相同但一个标保留区"的面板不能共用指纹。

**加密特化**：列集必须**开放**——加密可观测面在扩张（资金费/OI/爆仓/多空比/跨所价差），面板不能硬绑 OHLCV 五列（`10-crypto-fit.md` §7.1）；值对象本身用 `Mapping[str, ndarray]` 存字段，天然开放（固定五列是上游供给/求值白名单的事，不是 Panel 容器的事）。时间索引是 int64 纳秒、无时区语义，UTC 是构造契约（C7 无交易日历）。

## 具体例子 · 输入什么 / 输出什么（真实运行，非手写示意）

> 用 `venv/Scripts/python.exe` 直接构造 `Panel` 并调用其方法**实测打印**。复现按 `tests/tests/test_v5_label_panel.py:29-43` 的 `_panel` 构造；临时脚本在系统临时目录，未改仓库。

### 例子的场景（围绕加密货币）

20 根 1d bar、3 标的，字段 open/close/volume（价格随机游走），构造 `Panel(times, symbols, fields, holdout=None)`。

### 输入（构造参数，实测）

```
Panel(times = np.arange(20)*DAY_NS,        # int64 纳秒，UTC 构造契约
      symbols = ("S0","S1","S2"),
      fields  = {"open":(20,3), "close":(20,3), "volume":(20,3)},
      holdout = None)
```

### 输出（对象与方法返回值，实测）

```
shape            : (20, 3)
symbols          : ('S0','S1','S2')
fields           : ['close','open','volume']
times[0],times[-1]: 0, 1641600000000000
field("close").dtype = float64   shape = (20,3)
times.flags.writeable        = False     ← 构造后只读
field("close").flags.writeable = False   ← 字段只读
digest() = sha256:4e9c6c592351479d694c385f0f31eb1d6cb8861340dee053f3b98eae4611326b

```
→ 构造即转 float64 副本、只读；时间索引只读（约束不是"构造那一刻"的约束）。

### holdout 与切片（实测，panel holdout=(10,15)）

```
holdout_mask() True 的时点 = [10,11,12,13,14]           # 半开 [10,15)
slice_rows(12,18).holdout = (0, 3)                       # 部分重叠按交裁剪，重叠段仍不可用
slice_rows(0,10).holdout  = None                         # 无交集 → 不带保留区
slice.digest() != 母.digest() = True                      # 切片内容变、指纹变
```
`digest()` 含 holdout（`:170-174`）：一份"未标保留区"的面板不能顶替"已标保留区"的那份。

|---|---|

| 时间倒序 `times[::-1]` | `E4007` "时间索引必须严格递增且无重复（存在倒序）" |
| 字段形状 `(4,3)` vs 面板 `(5,3)` | `E4007` "字段 'close' 形状 (4, 3) 与面板 (5, 3) 不符" |
| 字段含 `inf` | `E4007` "字段 'close' 含 Infinity"（inf≠NaN，一定是算错） |
| 空时间轴 | `E4007` "时间索引为空" |
| 空标的清单 | `E4007` "标的清单为空" |
| 重复标的 `('S0','S0','S1')` | `E4007` "标的清单有重复" |
| `field("bogus")` | `E1014` "面板里没有字段 'bogus'" |
| `slice_rows(5,25)` 越界 | `E4007` "切片 [5, 25) 越界（共 20 根）" |
| `holdout=(3,9)` 但仅 5 根 | `E4007` "holdout 区间 (3, 9) 越界" |

## D2 · 差距（少什么 / 多什么 / 删什么 / 补什么）

| # | 差距 | 级别 | 证据 | 判断 |
|---|---|---|---|---|
| P-1 | **字段集开放（Panel 容器层✅），但"固定 OHLCV 五列"的 R3 缺口不在本模块**：Panel 用 `Mapping[str,ndarray]` 存字段、任意字段名可入（`:83,95-97`），不硬绑列；但求值白名单/供给仍倾向 OHLCV，加密流未接进面板。 | P0（R3 缺口，非本模块） | `panel.py:77-98`（开放字段集）；`10-crypto-fit.md:118,169` | **已确认本模块支持开放列集**：这是 R3 的有利基础，不是 Panel 的 gap。真正缺口在 read 多流 as-of（见 03_read R-1）与求值白名单。 |
| P-2 | **`as_field` 一律转 float64**：整数字段（如 `open_interest` 合约张数、`funding_rate` 高精度）被转成 float64。对 OI 这类大整数（>2^53）会丢精度；但因子计算以浮点为主，当前无影响。 | P2（精度边界） | `panel.py:66`（`astype("float64")`） | **需确认**：加密 OI/清算量若超 2^53 会有精度问题，但实践中合约张数远小于此。低优先，除非未来接链上原始整数数据。 |
| P-3 | **`times` 只校验 `dtype.kind in "iu"`、不校验落在 1900–2100**（与 `timeaxis.check_ns`/`read._checked` 不同）。直调 `Panel` 塞一个毫秒值 `1.7e12` 也接受（只要递增）。 | P2（校验深度不一） | `panel.py:33-45`；对照 `timeaxis.py:49-58` | **需确认**：经 align/read 产出的面板时间是正规纳秒；直调构造是内部入口。但与"1900–2100 sanity 唯一实现"的设计略有张力——可考虑复用 check_ns，或在文档写明 Panel 不负责时间单位校验。非本轮 bug。 |
| P-4 | **`digest()` 含 `holdout`、字段字节、标的序，但不含 `times` 的"单位语义"**（int64 自解释，无单位问题）——无实际缺口，仅说明。 | — | `panel.py:155-175` | 已确认正确，无需动作。 |

**多了什么**：无冗余。`slice_rows` 的"部分重叠按交集裁剪"是必要的防泄漏设计（`:122-145` 注释），非多余。

## D3 · 业界方案（借鉴什么 / 拒绝什么）

| 方案 | 裁决 | 加密理由 / 证据 |
|---|---|---|
| 不可变值对象（frozen dataclass + 只读 ndarray） | 采纳 | 构造即校验、下游改不了；"谁改过掩码/面板"在类型层不发生（`:77-107`） |
| pandas DataFrame（可变、列集固定） | **拒绝** | 可变性让"构造约束"退化；`Mapping[str,ndarray]` 天然开放列集，契合加密扩张（C8） |
| ffill/bfill 缺失值 | **拒绝** | 填充把缺席变值、截面排序当中间值；缺失用 NaN（`:7-8,66-74`） |
| `inf` 当缺失 | **拒绝** | inf 一定是算错（除零/溢出），必须 E4007，不能混同 NaN（`:67-72`） |
| holdout 切片"整体丢弃" | **拒绝** | 部分重叠按交裁剪，否则切后重叠段被当可用、"没看过保留区"失效（`:122-139`） |
| 内容寻址指纹（times+symbols+fields+holdout） | 采纳 | 避免"未标保留区"面板顶替"已标保留区"、换列序复用缓存（`:155-175`） |

## D4 · 代码问题（bug / 静默成功 / 口径漂移）

**已确认正确（逐条带证据）**：
1. **时间索引严格递增无重复**：`as_times` 检查 ndim=1、非空、整数 dtype、`diff>0`（`:27-50`），实测重复/倒序/空/浮点全 E4007。
2. **字段形状/类型/inf 校验**：`as_field` 检查 2D 形状匹配、数值 dtype、无 inf（`:53-74`），实测三类 E4007。
3. **标的清单非空无重复**：`:88-92`，实测空/重复 E4007。
4. **构造后只读**：`setflags(write=False)` 用于 times 与 fields（`:46-49,73`），实测 writeable=False；字段与 times 同一规则（不两套）。
5. **缺失 NaN、不填充**：`as_field` 不触碰 NaN（`:66`），`inf` 单独拒。
6. **holdout 半开区间校验与切片裁剪**：构造校验 `0<=start<=end<=size`（`:99-104`），`slice_rows` 按交集裁（`:134-144`），`holdout_mask` 逐时点（`:147-152`）——实测三者一致。
7. **digest 含 holdout 与列序**：`:170-174`（holdout）+ 逐字段按名排序 + 标的序（`:164-169`），实测切片 digest 不同、换列序 digest 不同。
8. **`field()` 缺字段 E1014**：`:114-120`，实测。
9. **`array_digest` 按字节**（含 -0.0/0.0 区分）：`:178-191`，用途是"同一次 vs 另一次计算"，非数值等价——设计意图明确。

**发现的问题**：
- 无 P0/P1 级代码 bug。P-1 是 R3 有利基础（本模块开放列集✅，缺口在上游）；P-2/P-3 为 P2（精度边界/校验深度不一）。测试覆盖充分（面板校验 `test_v5_label_panel.py:67-107` + 各能力间接）。

| 扩展场景 | 当前支持度 | 说明 |

| 时间单位/时区自动识别 | ❌ 不支持（也不应） | int64 纳秒是构造契约，不做换算（对齐 align 的 tz 立场） |

## C1–C12 相关项判定

- **C1 365 年化**：不适用（值对象，不算年化）
- **C7 24/7 缺口**：✅ 时间轴是 int64 纳秒、无交易日历；洞的语义由 align P5 负责（见 02_align）
- **C8 开放列集**：✅ **强相关**——Panel 容器天然开放任意字段（`:83,95-97`），是 R3 的基础；固定 OHLCV 五列是上游约束，非 Panel
- **C9 as-of ffill-only**：✅ 不适用本层——Panel 不填充任何值（缺失 NaN），as-of 对齐在 read 层
- **C11 流动性分层**：不适用（掩码在 boundary 的 Scope）

## R1–R7 影响

- **R1 真数据跑通**：✅ 支撑（所有能力都经 Panel 构造，真跑反复验证）
- **R2 结论可信**：✅ 强支撑——三条硬约束（递增/NaN/holdout）从值对象层杜绝伪显著与前视
- **R3 因子零代码扩展**：✅ **正向**——开放列集允许新加密流进面板（受 read 多流 as-of 能力制约）；这是 R3 难得的有利项
- **R5 单因子可归因**：中性（容器，不涉归因）
- **R7 fail-closed**：✅ 强支撑——构造即校验，10 类非法输入全实测拒

## 结论

**本模块是稳健的值对象，无 P0/P1 bug，可确认通过。** 三条硬约束（时间递增无重复、缺失 NaN 不填充、保留区不进面板）实测全部闭合；`digest()` 含 holdout/列序，`slice_rows` 部分重叠按交裁剪防泄漏。关键正面结论：**Panel 容器列集是开放的**（`Mapping[str,ndarray]`），"加密流未进面板"的 R3 缺口不在本模块，而在 read 的多流 as-of 对齐（见 03_read R-1）。P-2（float64 精度）、P-3（时间单位校验深度）为 P2，低优先。
