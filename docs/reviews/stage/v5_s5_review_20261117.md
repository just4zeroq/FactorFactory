## 2. ① bar 频率：把「年化基准」与「每年几根 bar」拆成两个量

### 2.1 问题

`capability/backtest_engine.py` 原来两处硬编码：

```python
_BASE_TS = pd.Timestamp("2020-01-01", tz="UTC")   # 造 1 天等距轴喂 ml4t
sharpe = mean / std * math.sqrt(365)              # 年化也按 365 次/年
```

后果不是「数字小一点」：接 1h 供给后**成交时点与真实数据无关**，且年报 Sharpe 被
系统性低估 √24 ≈ 4.9 倍。这正是 V4 那类「能跑、数不对」的假成功。

### 2.2 改法

`backtest` 增加**尾部可选输入 `time`**（UTC 纳秒 `int64`，与 `Panel.times` 同源）：

- `capability/ops/backtest.py:147` `_times()`：只收整数纳秒。**不转 float64**——
  纳秒量级 1.7e18 已超 2^53，转一次就把相邻 bar 压成同一时间戳。
- `capability/ops/backtest.py:180` `bars_per_year()`：`365 天 ÷ 中位步长`，
  返回 `(值, 来源)`。非等距（采集缺口）取**中位**步长：缺口是数据缺陷，不该改写
  标称频率。
- 输出新增 `bars_per_year` 与 `bars_per_year_source ∈ {time_axis_median,
  assumed_daily}`；`annualisation_used` 仍恒为 `calendar_365`。

两个量必须分开，因为它们不是一个东西：`calendar_365` 是**口径**（加密 24/7，
写进 `caliber.execution`，plan 只允许这一个值）；`bars_per_year` 是**数据频率**，
不能写进 `caliber`。同一口径下 1d 与 1h 的每年 bar 数差 24 倍。

### 2.3 生产链路真的传了

`orchestration/capability_bridge.py:135` `_panel_times()` 从 `Panel.times` 取轴，
两处 S4 子调用（Evidence 净成本链、Portfolio 尾链）都把 `time` 作为第 5 个输入传下去，
并校验 `times.size == aligned_price.shape[0]`。缺 Panel 时间轴直接 `E3003`——
**不允许**静默退回日频假设。

`backtest_engine.py:110` `_index_of()` 也从 `(stamp-base)//天` 改成时间轴最近邻匹配
（容差半步长）：真实轴非等距时，除法会在缺口后整体错位。

### 2.4 实测

| 场景 | `bars_per_year` | 来源 | 断言 |
|---|---|---|---|
| 不传 `time`（日频调用方） | 365.0 | `assumed_daily` | `sharpe` 与手算 √365 一致 |
| `time` 步长 1d | 365.0 | `time_axis_median` | — |
| `time` 步长 1h | 8760.0 | `time_axis_median` | `sharpe == 日频 × √24`（rel 1e-12） |
| `time` 步长 4h | 2190.0 | `time_axis_median` | — |
| 1h 轴含 5h 缺口 | 8760.0 | `time_axis_median` | 中位步长不受缺口影响 |
| `time` 长度 ≠ bar 数 / 非递增 | — | — | `E3003` |

## 3. ② S5：单步执行与 probe/commit 分流

### 3.1 之前的状态

`app/cli/station.py` 是一个 24 行的拒绝桩：永远 `E3001`（「无已落盘上游产物」）。
`Executor.execute()` 只认 `run`/`step`，`commit` 被当非法枚举（E1004）。
ticket 目录里也没有冻结方案，单步即使想跑也拿不到参数。

### 3.2 三块拼起来

**（a）冻结方案落盘** — `app/cli/run.py:20` `freeze_context()`
`run` 在执行前写 `frozen/plan.json`（编译后方案原文）与 `frozen/context.json`
（`station_params` / `station_impls` / `policy_view` / `policy_digest` /
`fingerprints` / `live`）。单步命令没有 `--plan`，构成只能来自磁盘——否则
「单步重放」就是「拿别的参数重算一遍」。写入用内容寻址的 `write_bytes`：同 ticket
重复 run 内容相同即幂等，内容不同直接拒绝。

**（b）写入范围由 `origin` 决定** — `orchestration/executor.py:131` `scope_dir()`
`step → steps/`，其余 → `parcels/`。目录名仍是
`<seq>-<Station>-<payload hex16>`，与正式产物同构。范围由产物自身的 origin 决定，
调用方不需要记参数。

**（c）单步执行** — `orchestration/executor.py:531` `execute_station()`
上游从**磁盘**取（`:644` `_load_committed()`：只读 `parcels/`，读回后重算
`payload_digest` 与声明比对，被改写即 `E3002`）；`append_only` 工位提交直接
`E3006`；commit 追加一条 `state.jsonl`；事件一律为空。

### 3.3 一个必须显式处理的语义：幂等提交

目录名含 `payload_digest` 前 16 位 → 「同名目录」等价于「同内容产物」。于是重算
得到同一 payload 时目录已存在，而 `log.jsonl` 里的时间戳必然不同，
`TicketWriter.write_bytes` 的「异内容拒绝覆盖」会判成 `E5004`（实测撞到，
`test_commit_writes_formal_parcel_and_state_without_events` 首次运行时暴露）。

正确做法**不是**放宽覆盖（那会打开改写历史产物的口子），而是幂等：
`:605` 检测到正式目录已有同 payload → 不重写产物、不追加状态、返回
`idempotent=true`。语义上也更准：这次提交没有产生新产物。

### 3.4 验收对照

| 项 | 判据 | 结果 |
|---|---|---|
| AC4 八工位均可单步 | 有落盘上游即可单步重放 | dummy 八工位全通；`--live` 下 Boundary/Panel 真跑（见 §4.2 边界） |
| AC6 重建失败显式 | 手改 `payload.json` → `failed` + 非零退出 | `E3002` + exit 1，且不留半成品 |
| AC7 单步隔离 | probe 后四项不变 | **硬判据**：ticket 目录新增文件只允许在 `steps/`、`logs/`、`trace.jsonl`，且零删除 |
| I7 commit 不触发事件 | `--commit` 不改账本 | `events=[]`；`--probe --commit` 同时给 → `E1001` |
| s0/05 §6 append_only | 提交式单步 → `E3006` | Search / Verdict 均 `E3006`（exit 1） |

AC7 的「试验计数」与「已发布结论」在结构上是不可变的：probe 是新进程、事件账本
还在内存（S5-M2 才落盘），probe 也不触碰 `parcels/`。硬判据用文件集合差分表达，
不依赖「看起来没变」。

## 4. 本轮修复的缺陷

1. **年化频率硬编码**（P0，S4 遗留 #3）：√365 写死，接小时线错 4.9 倍 → `bars_per_year`。
2. **成交时间轴造假**（P0，同源）：`2020-01-01 + i 天` 与真实数据无关 → `_axis()` 用真实纳秒。
3. **非等距轴索引错位**（P1）：`(stamp-base)//天` 在缺口后整体偏移 → 最近邻 + 半步长容差。
4. **commit 撞不可变写入**（P1，实测暴露）：同 payload 重提交报 `E5004` → 幂等短路。
5. **文档与实现分叉**（P2）：`steps/<Station>_<seq>/` 与实际 `steps/<seq>-<Station>-<hex>/`
   不一致，已统一（4 篇文档）。
