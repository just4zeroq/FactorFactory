# 16 · 凭据、权限与审计

> 本篇回答：**这套系统允许谁看到什么、改了之后能不能查、泄漏了怎么办**。
> 它不是安全合规文档，是**结论可信度的一部分**：如果 holdout 被谁在什么时候看过无法回答，那么「样本外结论」这句话就不能说。

---

## 1. 威胁模型

| 威胁 | 现实性 | 后果 |
|---|---|---|
| 交易所 API key 泄漏（进日志/产物/提交历史） | **高**（V4 的日志与报错直接打印配置） | 资损；且 key 泄漏通常伴随持仓暴露 |
| 提前查看 holdout，再据此调策略 | **高**（本来就是研究者自己） | 样本外退化成样本内，整套判据失效 |
| 事后修改试验计数或晋升记录 | 中 | 多重检验门槛失真，结论不可信 |
| 采集到被投毒的数据文件 | 低但致命（`long_liquidations` 是用户提供） | 因子学到的是别人塞进来的信号 |
| 多人共用一台机器 / 一个 workspace | 未来（Web 预留） | 身份与口径混淆：A 的结论跑在 B 的数据上 |

**不设防的东西**（明确写下，避免过度设计）：远程攻击面（没有常驻公网服务）、加密算法（用标准库）、操作系统级隔离（单人研究机）。

---

## 2. 凭据：值只在一个地方，其余全是引用

| 层 | 存什么 | 存在哪 | 允许出现在 |
|---|---|---|---|
| **值** | `apiKey` / `secret` / `password` / 代理口令 | 环境变量或 OS keystore（优先 keystore） | 只在内存里；进程退出即销毁 |
| **引用** | `credential_ref: "binance_main"` | 配置与 `Envelope` | 配置、`Envelope`、日志 |
| **派生物** | 指纹（如 `sha256(apiKey)` 前 8 位） | 记录里 | 用于「换没换 key」的判定，不可逆 |

三条硬规则：

1. **配置里只能写引用名**，不能写值。配置进 git，值不进。
2. **`Envelope` 只记引用面**（I15）；`Envelope` 会进产物与日志，所以它必须可公开。
3. **扫描拦截，不靠自觉**：CI 与运行期各有一个扫描器，在日志、Parcel、`--json` 输出、异常栈里找 `sk-` / 32 位以上高熵字符串 / 配置里的 key 字段名 → 命中即 `E2004` 并中止。

V4 的教训：报错处理会把整个 `exchange_config` 打进日志，其中含 `apiKey`/`secret`。V5 的异常类型不允许携带配置对象——要么传引用名，要么传脱敏后的字段清单。

## 3. 权限矩阵：四区 × 谁

| 区域 | 意图层 | 编排层 | 能力层 | 事实层 | 存储层 | 供给链 |
|---|---|---|---|---|---|---|
| **Charter**（章程，只读） | 读 | 读 | — | — | 读 | — |
| **Depot**（共享仓，只追加） | 编译期读 | 读 | 读 | 读 | 写 | **写** |
| **Ticket**（执行区，独占） | — | 写 | 只写本工位目录 | 读 | 写 | — |
| **Scratch**（暂存，可弃） | — | 写 | 写 | — | 写 | 写 |

两条结构保证（不是约定）：

- 能力层拿到的是**只读视图**，不是路径。它没有 `write()` 可调，所以「能力偷偷写 Depot」在类型上不成立。
- 存储层是唯一能落盘的层，且它对「目标区」做权限判定；越界返回 `E5004`（不是 `E2007`：这是存储层正常拒绝，不是契约违反）。

---

## 4. 审计链：三件不可逆的事

| 事件 | 记录内容 | 不可逆性 |
|---|---|---|
| **试验计数（Budget）** | `trial_family`、`n_trials` 增量、来源（交付/`fit` 内评估）、`ticket_id` | 只追加；清空等于换实验 |
| **揭示（Reveal）** | `period_key`、窗口区间、`revealed_at`、`ticket_id`、操作者标识 | **看过就是看过**；重复揭示被拒 |
| **发布（Publish）** | `factor_id`、`run_id`、判据快照、目标路径 | 只能新增版本，不能覆盖 |

审计回答三个问题，每个都必须能独立回答：

1. **谁看了样本外？** → 揭示账本按 `period_key` 反查 `ticket_id` 与操作者。
2. **这个因子凭什么被发布？** → 发布记录带判据快照（阈值 + 实际值 + `n_trials`）。
3. **门槛当时是多少？** → 判据快照 + `policy_digest`；阈值改了就是新实验，旧记录不受影响。

反例（V4 实际发生）：`reaudit --apply` 覆盖了 84/84 条原始 metrics，旧基线只能靠 `metadata_pre_reaudit/` 目录找回。V5 的做法不是「加个备份目录」，而是**登记库只追加、不可改写**。

## 5. 数据完整性

| 措施 | 做法 | 防什么 |
|---|---|---|
| 内容寻址 | 对象名 = 内容哈希；同名不同内容 → `E5004` | 静默改写历史数据 |
| 采集来源白名单 | 只允许配置里声明的交易所与端点 | 采集到非预期来源 |
| 校验和 | 每个发布版本带 `checksum`，门禁 A 校验 | 传输损坏、增量拼接错位 |
| 用户提供文件隔离 | `long_liquidations` / `short_liquidations` 这类无公开端点的流，落盘时标 `origin=user_supplied` | 投毒数据被当成交易所数据同等对待 |
| 只读执行 | 执行期对 Depot 零写入 | 单次执行污染共享事实 |

`origin=user_supplied` 的流在报告里必须单独列出。理由：它们的可信度与交易所数据不同，混在一起会让「数据来自哪里」不可回答——这正是 V4 把股票数据与加密数据混在 `data/` 里造成的同一类问题。

## 6. 泄漏与事故处置

| 事故 | 立即动作 | 后续 |
|---|---|---|
| key 进日志/产物 | 立刻 rotate key；停掉产出该日志的任务 | 扫描全部历史产物；把含 key 的产物标 `quarantined`，不删但不可引用 |
| key 进 git 历史 | rotate；历史重写由人决定（不自动做） | 在 `SECURITY.md` 记录时间线 |
| holdout 被提前看 | 该窗口作废；换下一个窗口 | 在揭示账本里写 `contaminated=true`，**不删除原记录** |
| 试验计数被改写 | 以追加记录为准；重建判据快照 | 受影响的结论全部标 `stale` |
| 数据文件被投毒 | 该版本作废；重新采集 | 所有引用该版本的产物标 `stale` 并重算 |

**共同原则：不删，只标。** 事故的处置痕迹本身是可信度的一部分；删掉痕迹会让「这件事发生过吗」也无法回答。

---

## 7. 未来多用户时的最小扩展点

现在不做，但契约要能接住：

| 需求 | 现在的形状 | 加什么 |
|---|---|---|
| 身份 | 无身份概念 | 应用层加身份；**身份只决定能看哪个 workspace，不决定口径** |
| 隔离 | 单 workspace | 执行区按 workspace 前缀分区；Depot 共享 |
| 谁改了口径 | `policy_digest` 已记录 | 记录里加操作者标识 |

明确不做：把身份塞进 `caliber`（那会让同一份策略因「谁跑的」而口径不同）、把权限做成可配置（权限是结构，不是参数）。

## 8. 不变量与验收

| 编号 | 内容 | 检查点 |
|---|---|---|
| **I53** | 凭据值只存在于内存与 keystore；配置、`Envelope`、日志、产物、`--json` 只允许引用名 | 扫描器四类目标全覆盖；命中即 `E2004` 并中止 |
| **I54** | 登记库（试验/揭示/发布）只追加，不存在改写路径 | 存储层对登记库无 `update`/`delete` API；篡改测试失败 |
| **I55** | 用户提供的流带 `origin=user_supplied`，并在报告中单列 | 报告缺该标记 → 发布被拒 |
| **AC54** | 凭据不落地 | 故意在异常里带配置对象 → 被扫描器拦下并中止；全量日志/产物扫描零命中 |
| **AC55** | 审计可回答三问 | 任一已发布因子：能查出谁揭示过哪个窗口、判据当时阈值、`n_trials` |
| **AC56** | 篡改可检测 | 手工改一条登记记录 → 校验失败（哈希链或校验和），系统拒绝继续使用该登记库 |
