# 12 · 阶段划分：S0–S7 与 E0–E4 的关系

> 本篇解决两个编号体系并存的问题。`05-contracts.md` §5 用 **E0–E4** 描述「能力成熟的里程碑」，`s0/README.md` 用 **S0–S7** 描述「交付阶段」。
> 两套编号此前只在 s0 的「非目标」表里出现过 S2–S7 的名字，**没有任何文档定义它们的范围与退出门槛**——这意味着「S3 做完了吗」无法回答。

---

## 1. 两套编号不是一回事

| 体系 | 回答 | 粒度 | 使用者 |
|---|---|---|---|
| **E0–E4** | 「这套设计的能力到哪一步了」 | 功能切片，可以并行 | 架构评审 |
| **S0–S7** | 「这一版能交付什么、下一版不能承诺什么」 | 交付闸门，严格串行 | 排期与验收 |

二者是**多对多**：E1（编译）跨 S0 与 S1；E4（能力扩容）跨 S3 与 S7。**排期只认 S，验收只认 AC。**

| E 阶段 | 内容 | 落在哪些 S |
|---|---|---|
| E0 规格化 | 八步规格表、能力目录、四区布局 | S0 |
| E1 编译 | 三层合并、Blueprint、`caliber`、四个锚点指纹、C1–C22 | S0（契约）→ S1（真实编译） |
| E2 执行器 | 唯一 `execute()`、Parcel、状态机、唯一裁判 | S1 |
| E3 单步 | 依赖/失效校验、隔离产物、事件绑定、命令面 | S1（骨架）→ S5（提交语义） |
| E4 能力扩容 | 真实算法、真实数据、真实成本、组合域 | S2 / S3 / S4 / S7 |

---

## 2. S0 — 契约冻结（契约层已落地；编译器与执行器未实现）

**目标**：一套**会拒绝的系统骨架**。八工位全 dummy，除拒绝路径外不产出任何真实数字。

**交付**：`s0/` 六篇定义的七类结构、八个指纹、C1–C22、退出码、四区布局，外加**核心五条 CLI**（`run` / `station` / `explain` / `inspect` / `stations`，带 `--json` 信封与退出码）。

**为什么 CLI 必须在 S0 而不是 S7**：十二条验收里有十条要求「进程退出码为 N」。没有可执行入口，就只能断言 `exit_code_for("E1001") == 2` 这个纯函数——那证明的是映射表，不是「拒绝真的发生了」。命令面在 S0 冻结的只有这四条；其余十一条业务命令随 S5–S7 补齐，见 `09-app-storage.md` §2.2。

**退出门槛**（`s0/README.md` §6，十二条）：十二条非法输入全部被拒、错误码正确、退出码非零；外加一条正向冒烟（八个 Parcel、八条 trace、退出码 0）。

**明确不做**：任何真实数据、算法、成本、单步提交语义、日志轮转、组合域；`doctor` / `factors` / `promote` 等业务命令。

> S0 的价值不在「能跑」，在于**第一次证明「失败是有信号的」**。V4 的病是假成功，S0 是唯一能根治它的阶段。

---

## 3. S1 — 编排真实化（合成数据自检）

**目标**：把 S0 的 dummy 换成**真实编译 + 真实执行器**，但数据用**合成面板**，算法用**已知答案的桩**。

**为什么先做这个而不是先接数据**：编排错（事件触发两次、单步污染状态、指纹进不了产物）在真实数据上表现为「数字不对」，在合成数据上表现为「已知答案对不上」。后者能定位，前者只能猜。

**交付**：

| 项 | 内容 |
|---|---|
| 真实编译 | 三层合并、C1–C22 全量、`flow explain` 逐叶子来源 |
| 真实执行器 | 唯一 `execute()`、Parcel 落盘与指纹链、状态机、失效传播 |
| 合成数据 | 确定性几何随机游走面板 + **植入一个已知信号**（如 `close` 的 5 bar 反转）+ **一个纯噪声因子** |
| 桩算法 | 一个直接返回植入信号的确定性算法；一个返回噪声的算法 |

**退出门槛**：

1. AC1、AC3–AC5、AC7、AC10–AC12 全绿；
2. **已知答案自检**：植入信号 → 判据通过且 `n_trials` 等于实际评估数；纯噪声 → 判据拒绝，且拒绝原因可读；
3. 十次重放同一执行 → `parcel_digest` 逐位一致；
4. 把植入信号的符号翻转 → 结论跟着翻转（证明不是「总说不显著」的退化判据）。

**明确不做**：真实交易所、真实统计检验、任何成本。

---

## 4. S2 — 供给链真实化

**目标**：数据从 ccxt 进来，原子落成不可变文件，编译期现算 `Pin`。

> **已按 `19-supply.md` 简化**：不再有暂存/门禁 A/别名/租约，`Pin` 由
> `store.read_dataset` 在内存里构造（`version = checksum[:16]`）。下面的交付清单
> 是当时的形态，保留用于追溯。

**交付**：`s0/06-upstream.md` 的真实实现——分页采集、缺口判定、校验和、租约、别名、维护日志；`DataLoader` 的 ccxt-only 门径（`10-crypto-fit.md` §3.1）。

**退出门槛**：

1. AC13–AC17 全绿：新版本发布后旧版本仍可按引用读；就地覆盖被拒；末根未收盘 → `E4003`；
2. 断网/超时/半途失败各构造一次 → 不产生「半份」版本，退出码 4；
3. **一次真实的端到端**：从空目录开始 refresh → 得到可被编排层引用的版本 → 编译通过；
4. 同一份数据连发两次 → 内容寻址命中同一版本，不产生第二份。

**明确不做**：扩张标的池到全市场（这会让 S2 变成无底洞）；组合层成员枚举。

---

## 5. S3 — 搜索与评估真实化

**目标**：qweave 求值、deap 搜索、两层漏斗、试验计数、零分布与显著性校正全部接真。

**交付**：`evaluate` / `observe` / `verdict` 三个能力的真实实现；字段与算子注册表（`11`）；`Budget` 计数。

**退出门槛**：

1. AC20–AC23、AC29、AC37–AC39 全绿；
2. 同一表达式在 V4 与 V5 上算出的暴露逐位一致（对拍见 `14-test-strategy.md` §5）；
3. `n_trials` 与手工统计一致：GP 跑 300×10 → 累计 ≥ 去重候选数且显著大于最终种群；
4. **置换零分布的校准检查**：纯噪声面板上 `empirical_p` 的分布近似均匀（V4 的整行置换在带漂移面板上中位 `|t|=4.74 > 观测 3.46`，是 `p=0.95` 的根因）。

**明确不做**：任何净收益表述；组合层。

---

## 6. S4 — 成本与成交真实化

**目标**：`backtest` 接 ml4t，`caliber.net` 生效，资金费按事件走，两档输出同源。

**交付**：`build_backtest_config(calendar="crypto")`、杠杆、tiered 成本、`Ledger` 与 `summary`/`full` 聚合、分位构造与约束构造两条路径。

**退出门槛**：

1. AC9、AC24、AC26、AC28、AC33、AC34 全绿；
2. 年化比值检验：`calendar="crypto"` 与 `periods_per_year=365` 逐位相同；与不传 calendar 的比值 = √(365/252) = 1.2035（V4 实测 0.2517 / 0.2091）；
3. `full` 聚合回 `summary` 的净收益、成本三项、换手逐项相等；
4. 资金费 1h / 4h 两种结算网格、总额相同 → 聚合到同一 bar 后金额相等。

**这是「第一条可判定结论」的门槛**：S4 之前，任何「净成本后可交易」的话都不成立。

**明确不做**：前向认证、holdout 揭示。

---

## 7. S5 — 单步提交与账本推进

**目标**：把「观察」与「提交」彻底分开，让重放不可用于刷结论。

**交付**：`--probe` / `--commit` 语义、状态机推进、事件的一次性、恢复执行。

**退出门槛**：

1. AC4–AC8、AC19 全绿；
2. 单步 `--probe` 后：试验计数、事件账本、正式状态、已发布结论**四项全不变**（逐项断言，不是「看起来没变」）；
3. `--commit` 允许覆盖产物但**不触发事件**；尝试触发 → `E3006`；
4. 断电式中断（进程 kill）后恢复 → 不重复计数、不重复揭示、不重复发布。

**明确不做**：跨进程/服务化执行（Q5 已收敛为单进程契约，见 `05-contracts.md` §7）。

---

## 8. S6 — 运维化

**目标**：让它能无人值守地跑，且坏了能查。

**交付**：日志轮转、缓存淘汰与容量上限、GC（引用计数 + dry-run）、告警阈值、结构化记录与 trace 的完整字段、`doctor` 的真实检查项。

**退出门槛**：

1. 连续 7 天无人值守运行，每天有可读的 `pipeline_<ts>.json`，无「成功但无产物」；
2. 磁盘占用不单调增长：删掉一个执行目录后 GC 能回收未被引用的对象（用引用计数断言）；
3. 人为制造六类故障（数据缺口、末根未闭合、租约冲突、holdout 已揭示、指纹失配、磁盘满）→ 每类都有预期退出码与一条可执行的修复建议（`15-operations.md` §4）。

**明确不做**：多机部署、跨地域复制。

---

## 9. S7 — 组合域与认证闭环

**目标**：从「单因子显著」走到「组合可交易结论」，且这条结论只能由认证段产生。

**交付**：组合域成员枚举与 `available_from`、退役监控、三段窗口、前向认证（walk-forward）、holdout `plan`/`reveal` 账本、可复现清单。

**退出门槛**：

1. AC18、AC19、AC25、AC27、AC30 全绿；
2. 组合层样本内表现**不能**被用来发布结论（尝试发布 → 拒绝）；
3. holdout 窗口只揭示一次；重复揭示 → 拒绝且账本可查；
4. 认证段与组合层使用同一 `caliber_digest`（只允许数据不同）。

**明确不做**：自动调门槛。DSR 全失败是结论，不是故障——V4 实测 71 试验下门槛年化 SR ≈1.4，而最强朴素信号仅 0.675，差距在信号量级，不在门槛。

## 10. 阶段间依赖与「最小可信纵切」

```
S0 契约 ──▶ S1 编排 ──▶ S2 数据 ──▶ S3 搜索/评估 ──▶ S4 成本 ──▶ S5 单步提交 ──▶ S6 运维 ──▶ S7 组合/认证
                              │                                        │
                              └──── 可并行：S2 与 S3 互不阻塞 ─────────┘
```

| 想得到什么 | 最少要走到 |
|---|---|
| 「系统会拒绝」 | S0 |
| 「编排是对的」 | S1 |
| 「数据可复现」 | S2 |
| 「显著性判据可信」 | S3 |
| 「净成本后可交易」这句话成立 | **S4** |
| 「可以无人值守」 | S6 |
| 「可以发布可交易结论」 | **S7** |

**最小可信纵切 = S0 → S4**。S5–S7 提升的是**可信度与可持续性**，不是「能不能算出数」。反过来，跳过 S1 直接接数据，会得到一条「跑得动但不知道错在哪」的流水线——V4 就是这样。

## 11. 每个阶段都不许提前做的事

| 阶段 | 禁令 | 违反的后果 |
|---|---|---|
| S0 | 不许接真实数据或算法 | dummy 产物被当成真实结论 |
| S1 | 不许报告任何统计显著性 | 合成数据上的 p 值没有意义 |
| S2 | 不许扩标的池 | 供给链未稳定就扩池 = 把不确定性乘以 N |
| S3 | 不许说「找到 alpha」 | 未过成本口径的显著性是构造诊断 |
| S4 | 不许无人值守 | 成本口径未验证就跑批 = 批量生产错误数字 |
| S5 | 不许用重放救结论 | 「重跑到通过」是免费重试 |
| S6 | 不许放宽告警换安静 | 告警被静音等于没有告警 |
| S7 | 不许调门槛 | 门槛是预注册的判据，不是待优化参数 |
