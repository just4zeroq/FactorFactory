# 14 · 测试与拒绝策略

> 本篇回答：这套系统的测试**该测什么**，以及为什么「测试很多」并不等于「结论可信」。
> V4 的实测是最好的论据：**771 个测试全绿**，同时存在至少 **11 处假成功**（退出码 0、界面正常、报告有数，但实际没跑或算错）。测试密度不缺，缺的是**测在错误的位置上**。

---

## 1. 为什么测试要独立成篇

| V4 的假成功（实测） | 为什么现有测试没抓到 |
|---|---|
| `cli.main()` 丢弃返回值 → 退出码恒 0 | 测试直接调函数断言返回值，从不走进程退出码 |
| `gap_filler` 只 `success_count += 1`，从不下载 | 断言的是计数增加，不是文件存在 |
| 下载保存失败仍返回 `success: True` | mock 掉了保存层，测的是「调用发生过」 |
| `/ws/monitor` 100% 握手失败 | 用 `TestClient` 走 HTTP，没走真实 websocket scope |
| `0 folds` 仍判通过 | 没有「零样本必须失败」的反例 |
| 前端 `pct()` 把 cagr 缩小 100 倍 | 前端零测试，后端输出正确 |
| 12/13 配置入场价与回测错位一根 bar | 每个组件单测都过，跨组件口径无人对账 |

共同点：**测的是「组件返回了什么」，不是「系统在坏输入下是否拒绝」以及「跨组件口径是否一致」**。
所以本系统的测试重心必须从「功能覆盖率」转向 **拒绝矩阵 + 对拍 + 已知答案**。

---

## 2. 五层测试，各有各的失败形态

| 层 | 测什么 | 失败形态 | 数量级 | 何时写 |
|---|---|---|---|---|
| **L1 结构与指纹** | 规范化 JSON、八个指纹、类型校验 | 同一输入两种 digest | 数十 | S0 |
| **L2 拒绝** | 每条 C/I 约束都有一个坏输入 | 坏输入被静默接受 | **最多**（C1–C22 + I1–I61） | S0 起，逐阶段加 |
| **L3 对拍** | 与外部权威实现比数值 | 自己算的和标准实现不一致 | 十余 | S3–S4 |
| **L4 已知答案端到端** | 合成数据上的植入信号 | 该显著的没显著 / 该拒绝的通过了 | 个位数 | S1 起 |
| **L5 性能与资源** | 耗时、内存、缓存命中 | 慢一个数量级或内存爆掉 | 个位数 | S4 起 |

**优先级明确**：L2 > L4 > L3 > L1 > L5。理由：L2 拦住「算错了还说成功」，L4 拦住「整条链逻辑错」，L3 拦住「单点实现错」。L5 只影响能不能跑，不影响结论对不对。

---

## 3. L2 拒绝矩阵（本篇的核心）

每个约束都必须有一条**能构造出来的坏输入**，并断言**错误码 + 退出码 + 不产生副作用**三件事。

### 3.1 按来源分类

| 类 | 典型坏输入 | 期望 |
|---|---|---|
| **配置** | 拼错实现名 / 多余参数 / 类型错 / 构成性参数走命令行 | `E1002` / `E1003` / `E1004` / `E1005`，退出码 2 |
| **口径** | 工位参数里写 `horizon` / `cost_tiers` / `entry` | `E1020`，退出码 2 |
| **注册表** | `shift(-1)` / `center=True` / `bfill` / 引用未注册字段 | `E1015` / `E1014`，退出码 2 |
| **数据** | 别名指向不存在版本 / 末端未闭合 / 校验和不符 | `E4001` / `E4003` / `E4004`，退出码 4，**且不创建 Ticket** |
| **产物** | 手改 Parcel 不改 digest / 上游缺失 / 产物为空 | `E3002` / `E3001` / `E3003`，退出码 1 |
| **权限** | 能力层取时钟 / 写 Depot / 调未声明子能力 | `E2007` / `E5004` / `E2008`，退出码 3 |
| **事件** | 单步推进正式状态 / 重复揭示 / 重复计数 | `E3006`，退出码 1，且账本不变 |
| **应用** | 无 `--yes` 调 `promote` / `--json` 与退出码不一致 | 退出码 2 / 断言不一致即失败 |

### 3.2 三条写法规则

1. **断言副作用为零**，不只断言异常。「被拒绝」还不够，必须断言**没有创建 Ticket、没有写账本、没有落产物**。
2. **断言错误码，不断言消息文本**。消息会变，码是契约。
3. **一条坏输入一个测试**。合并成「参数校验测试」之后，某一条失效不会被发现。

### 3.3 拒绝矩阵的自动核对

C1–C22、I1–I61 各自维护一个 `id → 测试名` 映射。CI 里跑一个元测试：

```
断言：每条 C/I 都有至少一个测试引用它（按 id 字符串匹配）
断言：没有测试引用不存在的 id
```

这条元测试的价值在于**防止约束增加而测试不增**——V4 的 `shift` 白名单就是这么漏的。

### 3.4 按工位的拒绝用例与已知答案

上一张表按「来源」分类，方便写测试；这一张按「工位」分类，方便回答「这一步测够了没有」。每个工位至少两条拒绝用例 + 一条正向用例，缺任一条视为该工位的测试未完成。

| 工位 | 必须构造的拒绝用例 | 正向 / 已知答案用例 | 断言要点 |
|---|---|---|---|
| `Boundary` | `k` 超可选标的数（`E1004`）；时间轴越出已固化覆盖（`E4002`）；用当日成交额判当日准入（因果，整步失败） | 20 资产固定池：前 10 bar 因历史不足不入池 | 两张掩码逐格与手算一致，且**不同源**（同一张表复制两次必被抓） |
| `Panel` | 声明 `basis` 但供给无该文件（`E1014`）；末根 bar 未收盘（`E4003`）；某字段整列为空（`E3003`） | 注入一份「晚于收盘 1 秒」的快照 → 必须被丢弃并记入 `unclosed_dropped` | `causal_report.field_lags` 逐项等于注册表；`quality_report` 六个字段齐全 |
| `Target` | `min_width=40` 而某时点仅 30 个成员 → 该时点被丢且计数；`rebalance < horizon` 且未声明重叠（`E1022`）；丢弃时点占比 21% → `E3003`（I61） | 植入 `-returns` 5 bar 均值 → `label` 与手算 `close[t+5]/close[t]-1` 逐位一致 | `dropped_bars.by_reason` 之和 = `count`；`overlap_policy_used` 逐字等于 `caliber`；`quality_report` 记丢弃数与区间 |
| `Search` | `shift(-1)`（`E1015`）；产出超配额（`E1017`）；算法读测试段（`AttributeError`）；数据版本变化后用同一计划重跑 → `E1009`（I59） | 桩算法返回植入信号 → `count` 与 `dedup_digest` 可复算 | `n_trials >= count`，且 `fit` 内评估也计数（I38 / AC38） |
| `Evidence` | `null_model` 不在冻结口径里（`E1003`）；候选为空（`E3003`）；观测里出现 `pass` / `significant`（`E2004`） | 纯噪声面板 200 次置换 → `empirical_p` 近似均匀（KS 不拒绝） | 只产观测；`single_factor_net_ref` 必须来自同一 `allocate`+`backtest` |
| `Verdict` | 配置指定第二个裁判（`E1002` / `E2006`）；`criteria_digest` 非 `policy_digest` 子集（`E3002`）；`n_trials_used` 由参数传入（`E2003`） | 植入信号 → `pass`；纯噪声 → `reject` 且原因可读 | `reason_counts` 之和 = 候选数；同输入两次结论逐字一致 |
| `Portfolio` | 运行期增删成员（`E3006`）；`eval.start < fit.end + embargo`（`E1021`）；`members` 为空（`E3003`）；跨执行域成员未显式声明（`E1018`，I60） | 3 因子等权小样本 → 权重与手算一致 | `evidence_grade` 恒 `in_sample`；`binding_constraints` 与实际约束一致 |
| `Certify` | `folds_detail` 为空（`E3003`）；用组合层样本内表现发布（`E3006`）；重复揭示 holdout（`E3006`） | 认证段复算：`caliber_digest` 与组合层逐字相同 | `metrics` 键带单位后缀；`reproducible_manifest` 六项非空 |

**`Certify` 的四条空样本反例必须单独写**（V4 的 `0 folds` 判通过就是这里漏的）：0 折、1 折且样本不足、全折无有效观测、折间窗口重叠——四条都要求非零退出码，而不是「指标为空但不报错」。

## 4. L4 已知答案：合成数据必须能证伪

真实数据上「结论对不对」永远无解。合成数据上可以。

### 4.1 面板契约

| 项 | 规定 |
|---|---|
| 规模 | 20 资产 × 200 bar（够算 60 bar 滚动，够分 5 折） |
| 生成 | 固定种子 + 几何随机游走 + 指定漂移与波动 |
| 植入信号 | 一个已知的横截面反转（`-returns` 的 5 bar 均值），强度可调 |
| 噪声对照 | 纯随机因子，与收益无关 |
| 落盘 | 内容寻址 + `golden_panel_digest`，任何改动都换 digest |

### 4.2 四条断言（缺一不可）

| # | 条件 | 期望 | 反例说明 |
|---|---|---|---|
| 1 | 植入信号，强度足够 | 判据通过 | 判据太严会把真信号也拒掉 |
| 2 | 纯噪声 | 判据拒绝 | 判据太松 → 什么都过 |
| 3 | 植入信号符号翻转 | 结论跟着翻转 | 防止「结论与因子方向无关」的假判定 |
| 4 | 植入信号置零（只剩噪声） | 与 #2 一致 | 防止「只要有数据就说显著」 |

**第 3 条最容易被忽略**：只测「显著/不显著」时，一个把结果取绝对值的 bug 也能通过全部测试。

### 4.3 数据版本必须进断言

同一份 golden 面板跑两次，`parcel_digest` 必须逐位一致；换一个 `golden_panel_digest` 后，旧产物必须标 `stale`。这两条同时验证「落盘可重建」与「指纹真的覆盖了数据」。

### 4.4 真实数据已知答案：`mom60 @ 5 bar`（黄金面板锚点）

合成数据只能证明「系统对植入信号有反应」。还需要一条**真实数据上的已知答案**，证明整条链的数值量纲没有错位——这是 AC63 的第二半。

**裁决（2026-11-17）：锚点不依赖 V4 的任何内容**。V4 历史数据（`data/binance/**` feather）与 V4 实测值 0.675 都不再参与验收：前者不导入（历史数据直接弃用），后者只作量级背景（真实币圈面板上朴素动量的年化净 SR 是 O(0.5~1)，不是 6.75 也不是 0.0675——两个数量级错误正是这条对拍要抓的）。锚点改为在 **V5 自采数据冻结的黄金面板**上由**独立复算**测定并冻结：

| 项 | 规定 |
|---|---|
| 信号 | `mom60`：过去 60 根 bar 的收益（`ret(close, 60)`），截面排序构造多空 |
| 面板 | **黄金面板**：V5 自采（ccxt）20 USDT 永续 1d，窗口 `[2023-01-01, 2026-06-30]`；逐符号 checksum 记入数据根 `db/golden_panel.json`，面板变即锚点作废、重新冻结 |
| 口径 | 基线 `h=5 / rebalance=5 / next_close`（`entry offset` 已把成交延迟编进标签，与回测链 `NEXT_BAR` 逐格同构）；换口径即换对拍基准 |
| 期望值 | 冻结时由**独立复算**（手写 pandas 参考实现，不 import `v5`）测定的 `gross_sharpe / gross_return / sr / turnover / n_periods`，写入 `db/golden_panel.json` |
| 容差 | 两层：① 流水线 vs 独立复算（同数据同口径的决定论量）**相对误差 `1e-9`**——浮点求和顺序差异真实存在，超出即实现分叉；② 跨版本重跑 vs 冻结期望值 **±10%**——防实现重构后漂移 |
| 计数 | `n_trials` 必须等于预注册枚举的实测去重候选数（单先验时 = 1）；只登记最终种群 → 失败（AC38） |

**为什么容差能收紧**：原 ±10% 是为「不同收益来源下的小幅漂移」留的；锚点改到同一份冻结面板后漂移来源消失，剩下的只有浮点顺序差，故对拍容差收到 `1e-9`。±10% 保留给第二层（跨版本回归），不许用它掩盖实现分叉。

**它不是用来找 alpha，是用来找量纲错误**：算出 10 倍说明年化或杠杆错了；算出 1/10 说明周期或成本单位错了。V4 出现过 CAGR 缩小 100 倍、`1M` 年化返回 525600、年化用 √252 而非 √365，全都会在这条对拍上暴露。

**`passed=0` 不是失败信号**：朴素动量的年化量级（O(0.5~1)）远低于 `n_trials=255` 的 DSR 门槛 1.53。验收看的是「量纲有没有错位」，不是「有没有因子过闸门」。把这个顺序倒过来，就会用调门槛代替修量纲。

## 5. L3 对拍：与谁比、容差多少

| 项 | 对手 | 容差 | 实测依据 |
|---|---|---|---|
| BH / BY 校正 | statsmodels（仅 dev 依赖） | **逐位**（差 `1.11e-16`） | 实测两实现逐位相同，故不给容差 |
| 年化 | 同一条曲线两种算法 | 逐位；与不传 calendar 的比值 = 1.2035 | 0.2517 / 0.2091 |
| 回测指标 | 手算小样本（3 资产 × 20 bar，逐笔可核） | 逐位 | 指标多但样本极小，可人工核对 |
| 表达式求值 | 手写 pandas 参考实现（仅测试用） | `1e-12` 相对误差 | 浮点顺序差异真实存在 |
| 资金费聚合 | 两种结算网格 | 逐位 | I34 / AC34 |
| 因子暴露 | 手写 pandas 参考实现（同表达式同面板） | `1e-12` 相对误差 | 原「V4 evaluator 逐位对拍」（`13-migration.md` §5）已按 2026-11-17 裁决取消：不依赖 V4 任何内容，参考实现改为 pandas 手写 |
| 真实数据已知答案 | `mom60@5bar` 与黄金面板的独立复算 | **`1e-9` 相对**（决定论量）；冻结期望值回归 **±10%** | §4.4；AC63 |

**为什么有的给容差有的不给**：能被精确规定的（整数计数、校正后 p 值、两种算法算同一量）就必须逐位；涉及浮点求和顺序的才给相对误差，且容差写在测试里而不是「大致相等」。

## 6. L5 性能与资源回归

基线全部来自本机实测，允许退化 **1.5×**，超过即失败（不是警告）。

| 场景 | 基线 | 允许上限 |
|---|---|---|
| ml4t 回测 20 资产 × 1187 bar，每 5 bar 调仓 | 0.388 s | 0.58 s |
| qweave Alpha158 全量（158 因子） | 17.3 ms | 26 ms |
| 单表达式重算 23.7k 行（批量摊薄） | 0.2 ms/次 | 0.3 ms |
| 约束构造（`cvxpy` `Parameter` 复用） | 1.47 ms/bar | 2.2 ms |
| 纯分位构造全panel | 1.01 ms | 1.5 ms |
| duckdb 100 因子跨文件聚合 | 24 ms | 36 ms |
| 因子相关（两因子） | 6 ms | 9 ms |

另两条硬断言：

1. **默认配置下不存在节点级磁盘缓存目录**（实测净亏 65×：LRU 0.001 ms vs parquet 13.3 ms），`08-reuse-audit.md` §8。
2. **约束路径 237 次调仓只 canonicalize 一次**（计数断言，AC30）。

**性能测试不设「平均通过」**：单次超限即失败，避免用多次取均值稀释退化。

## 7. CI 门禁

| 触发条件 | 动作 |
|---|---|
| 任一 L2 拒绝测试红 | **阻断合并** |
| 元测试发现约束无对应用例 | **阻断合并** |
| 任一 L3 对拍超出容差 | 阻断合并 |
| L4 已知答案四条断言任一红 | 阻断合并 |
| L5 超 1.5× 基线 | 阻断合并（附 profile 报告） |
| `--json` 与退出码不一致 | 阻断合并 |
| 文档 YAML 与 `plan_schema.json` 不一致 | 阻断合并（`tests/test_plan_schema.py`，AC61） |
| 日志/产物里出现凭据或绝对路径 | 阻断合并 |
| 覆盖率下降 | **只报告，不阻断** |

**为什么不设覆盖率门槛**：覆盖率衡量「执行过的行」，不衡量「拒绝过多少坏输入」。V4 覆盖率不低，假成功照旧。真正该盯的是「每条约束都有反例」——那是一个计数，不是一个百分比。

---

## 8. 反模式

1. **`assert result is not None`**：锁死了「有返回值」，不锁语义。V4 大量测试长这样。
2. **只测 happy path**：本系统 80% 的价值在拒绝路径上。
3. **mock 掉被测逻辑本身**：mock 了「保存」，然后断言「保存被调用」——保存失败仍会绿。
4. **把 flaky 标 `skip`**：flaky 通常意味着依赖了时间/随机/网络，而这正是本系统最需要确定性的地方。修它，或把不确定性注入进来。
5. **用真实网络做测试**：CI 必须离线可跑。网络只在 S2 的「一次真实端到端」里出现，且单独标记。
6. **对拍用同一个库**：拿 qweave 对 qweave 不叫对拍。对手必须是不同实现，或手算。
