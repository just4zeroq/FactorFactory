# 11 · 字段与算子注册表

> 本篇回答一个问题：**一个因子表达式允许引用什么**。
> 这个问题有三个消费者：编译期校验（C16 / C17）、指纹（`operators_version` / `fields_digest`）、以及运行期求值时的缺列判定。
> 三处各写一份清单，就必然出现三份不一致的清单——V4 的 `shift(-1)` 前视因子就是这么进来的：算子白名单里有 `shift`，但没人检查参数符号。

---

## 1. 为什么必须有注册表，而不是散在各处的常量

| 现象（V4 实测） | 根因 | 注册表怎么根除 |
|---|---|---|
| `{"op": "shift", "args": [-1]}` 能构造完美前视因子 | 白名单只查算子名，不查参数域 | 算子条目带 `param_domain`，负位移不在域内 → `E1015` |
| 31/84 个因子快照 `std > 1e6`，最大 5.67e19 | `_safe_divide` 把 0 分母替换成 `1e-9` | 除法条目声明 `degenerate_policy`，分母下限按量纲给出，不写魔数 |
| 3 个全零常数因子被当成「有效因子」入库 | 没有退化判定 | `field` / `op` 之外增加 `degenerate_check`，常数暴露整批拒绝 |
| `operators_version` 取 `qweave.__version__` | 指纹来源错位 | 取**算子表内容哈希**（I27 / AC29） |
| 声明 `basis` 但本地没有文件，面板静默少一列 | 缺列判定散落在 loader | 供给覆盖与声明字段在编译期对账 → `E1014` |

结论：注册表不是文档附属物，它是**编译期输入**。它必须可被程序读，文档只是它的人类可读投影。

## 2. 字段注册表

### 2.1 条目结构

| 字段 | 含义 | 例 |
|---|---|---|
| `name` | 表达式里能写的名字 | `close` / `funding_rate` |
| `causal_class` | 时点语义，决定对齐方式 | `bar`（已收盘 bar）/ `event`（事件时点）/ `static`（合约静态属性） |
| `source` | 来自哪条供给流 | `ohlcv` / `crypto_stream:funding_rate` / `market_meta` |
| `dtype` | 数值类型 | `float64` / `category` |
| `unit` | 单位，写进字段名后缀，渲染层不换算 | `usd` / `bp` / `ratio` |
| `available_lag` | 相对 bar 的可用滞后（bar 数），只允许 `>= 0` | `0` 表示当根收盘后即可用 |
| `pivotable` | 是否可进入横截面面板 | `true` / `false`（如 `expiry` 只能做分组键） |
| `note` | 因果说明（为什么这个滞后是 0 而不是 1） | 见 §2.3 |

### 2.2 当前清单（V4 已有供给，S2 冻结）

**OHLCV（`source=ohlcv`，`causal_class=bar`）**

| 字段 | unit | 说明 |
|---|---|---|
| `open` / `high` / `low` / `close` | usd | 交易所返回的原始四价，不做复权（加密无拆股） |
| `volume` | base_ccy | 基础币成交量；**quote 成交额由 `close * volume` 派生，不单独存**，避免两份真相 |
| `vwap` | usd | **派生字段**：`(high + low + close) / 3`。qweave 的 Alpha158 需要它；取不到真实成交均价时这是唯一可复现的定义，必须写进注册表而不是各算各的 |
| `returns` | ratio | `close / close[t-1] - 1`，`available_lag=0` |

**加密流（`source=crypto_stream:*`，`causal_class=event`）**

| 字段 | unit | 可用时刻 | 说明 |
|---|---|---|---|
| `funding_rate` | ratio | 结算事件时刻 | 实测结算间隔有 1h / 4h / 8h 三种且同一合约会变（I34）；只允许按事件求和，不得按固定周期乘 |
| `open_interest` | base_ccy | 快照时刻 | 交易所快照频率与 bar 不同频，对齐时允许 `ffill`（过去→现在），不得 `bfill` |
| `basis` | ratio | 同 bar 收盘 | `(perp_close - spot_close) / spot_close`；两个价都必须已收盘 |
| `long_liquidations` | base_ccy | 快照时刻 | **用户提供**（无免费公开端点），缺文件不报错但该列不可引用 |
| `short_liquidations` | base_ccy | 快照时刻 | 同上 |

**合约元数据（`source=market_meta`，`causal_class=static`）**

| 字段 | 用途 | 陷阱 |
|---|---|---|
| `underlying` | 同一标的的多合约归组 | `BTC/USDT:USDT` 与 `BTC/USD:BTC` 是**同一 underlying、不同 instrument**（`10-crypto-fit.md` §7.2） |
| `contract_type` | 排除非永续（交割/期权） | 只能用快照时点的值，不能拿今天的分类回填历史 |
| `expiry` | 期限结构因子 | 永续为 `NaT`，不得填 0 |
| `settle` | 结算币种 | 直接决定 PnL 的计价单位 |
| `quote_ccy` | 报价币 | 与 `settle` 不同时，成本口径必须显式处理 |

**掩码（不是字段，但表达式可以引用）**

| 名字 | 语义 | 谁产生 |
|---|---|---|
| `observable` | 该时点该标的进入统计与中性化 | Panel 工位 |
| `tradable` | 该时点该标的可下权重 | Boundary 工位（流动性分层） |

### 2.3 因果声明必须写清「为什么是 0」

`available_lag` 只允许 `>= 0`，且每条必须有一句可反驳的理由。范例：

- `close.available_lag = 0`：bar `t` 的收盘价在 `t + 1 bar` 开盘前已知；标签用 `close[t+h] / close[t]`，与因子同索引不构成前视（V4 已核实）。
- `funding_rate.available_lag = 0`：结算事件发生在 bar 边界，事件本身是公开的。
- `open_interest.available_lag = 0`：快照带时间戳，早于该 bar 收盘的快照才可用；**同一 bar 内晚于收盘的快照必须丢弃**。

反例（V4 真实缺陷）：把「当日收盘后发布的指标」当 `available_lag=0`，再用它算当日收益。

## 3. 算子注册表

### 3.1 条目结构

| 字段 | 含义 |
|---|---|
| `name` | 表达式里的算子名 |
| `arity` / `types` | 参数个数与类型签名 |
| `window_kind` | `trailing`（唯一允许）/ `centered` / `expanding` |
| `param_domain` | 参数取值域；窗口必须是正整数，位移必须是 `>= 0` |
| `cost_class` | 求值代价档（用于粗筛预算预估，不参与判据） |
| `degenerate_policy` | 退化输入怎么处理：`nan` / `reject_batch` |
| `since` / `deprecated` | 引入与废弃版本 |

### 3.2 全局禁令（违反即 `E1015`）

| 禁令 | 为什么 |
|---|---|
| 负位移 `shift(-n)` / `lead(n)` / `future_*` | 直接把未来值搬到当前行。V4 的白名单放行了算子名却没查符号，实测可构造完美前视因子 |
| 居中窗口 `center=True` / `rolling(center)` | 窗口跨过当前 bar 取未来值 |
| 反向填充 `bfill` / `backfill` | 把未来观测搬到过去 |
| `pct_change(periods < 0)` | 同上，换个名字的负位移 |
| 任意常数分母 | 见 §3.3 |

### 3.3 退化输入：不许用魔数兜底

`_safe_divide(x, 0)` 在 V4 里变成 `x / 1e-9`。后果不是「一个 NaN」而是**整批数量级爆炸**：31/84 快照 `std > 1e6`，最大 5.67e19，随后 `rank()` 把这些值排成噪声顺序。

注册表规定：

1. 除法条目的 `degenerate_policy` 只能是 `nan` 或 `reject_batch`，**不接受任何常数替换**；
2. 分母的合法性判定按量纲给相对下限（如收益率分母 `1e-8`，价格分母 `1e-8 * close`），下限本身进算子表参与哈希；
3. 每批暴露落盘前做退化检查：`std == 0` 或非有限值占比超阈值 → 整批拒绝（`E2004`），不静默入库。

## 4. 版本与指纹

| 指纹 | 组成 | 变化时 |
|---|---|---|
| `operators_version` | **算子表内容哈希**（名字、签名、域、策略、`since`），不取 `qweave.__version__` | 缓存全失效；下游标 `stale`；AC29 |
| `fields_digest` | 字段注册表内容哈希（名字、`causal_class`、`available_lag`、单位） | 编译期重新对账供给覆盖 |
| `supply_digest` | 已固化的供给版本（`Pin` 集合） | 新试验族（WQ1） |

**为什么不用包版本号**：fork 之后 `qweave.__version__` 不变而算子语义已变，两套算子会算出同一个 digest——缓存与对照同时失效，且没有任何报错。这是 I27 的全部理由。

### 4.1 注册表落在哪、谁读它

前几版只说了「注册表是编译期输入」「`operators_version` 取内容哈希」，没说它**是一个文件还是一个类**。不写清这一条，实现时会出现三份注册表（配置里一份、`qweave` 里一份、代码里一份），而三份都自称权威。

| 项 | 位置 | 形态 | 谁读 |
|---|---|---|---|
| 字段注册表 | `capability/registry/fields.json` | 契约数据（与 `plan_schema.json` 同性质，不是业务代码） | 编译器（C15 / C16）与 `plan_schema` 校验 |
| 算子注册表 | `capability/registry/operators.json` | 同上 | 编译器（C17）、`evaluate` 求值前的白名单检查 |
| 唯一加载器 | `capability/registry.py` | 代码，只有它读上面两个文件 | 编译期读一次，之后只读内存 |

四条规则：

1. **JSON 是真相，代码里不得再有常量表**。字符串白名单、算子名集合这类常量一旦写进 `.py`，就会与 JSON 各说一套，且测试通常只覆盖其中一份。
2. **加载即自检**：窗口 ≤ 0、负位移、`center` 窗口、`bfill` 类语义、缺 `impl_symbol`，任何一条不满足就整体加载失败（`E1015`），不做「跳过这一条」。跳过等于把它从注册表里悄悄删掉。
3. **`impl_symbol` 显式映射到 qweave 的函数名**。qweave 不支持注册自定义算子，所以注册表只能声明「我用它的哪个函数」；映射缺失即加载失败，不靠名字猜。
4. **指纹只按文件内容算**：`operators_version = sha256(canonical(operators.json))`，不含模块路径、不含加载时间。这样「只改了注释」不会让缓存全失效，「只改了一个枚举顺序」会让它失效——后者确实改变了语义。

`tests/test_plan_schema.py` 已经把 `plan_schema.json` 与文档做了双向核对；注册表落地时照同一形态补一组（AC41 / AC43），否则本节又只是一段描述。

## 5. 校验流水线

```
plan.caliber + search.algorithms[].ops
        │
        ├─ C16 算子白名单 ── 未注册 / 在禁令表 → E1015（编译期，退出码 2）
        ├─ C17 字段覆盖   ── 声明字段 ⊄ 已固化供给覆盖 → E1014（编译期，退出码 2）
        └─ AST 因果扫描   ── 负位移 / 居中窗口 / 反向填充 → E1015，附算子与参数位置
                │
                ▼
        运行期求值：缺列 → E4002（供给不适用），不返回 NaN 蒙混
```

三条规则：

1. **编译期拒绝优先于运行期发现**。能静态判定的，一律编译期报错；运行期只留「数据真的缺了」这一种情况。
2. **拒绝要指位置**。错误消息必须带算子名、参数下标、表达式的 JSON Pointer，而不是「因子非法」。
3. **注册表本身有测试**。给算子表加一条空窗口的 `rolling(0)`，必须有测试失败（AC41）。

## 6. 内置因子清单不是注册表

内置因子（Alpha158 那 158 个）是**候选的预置来源**，不是字段/算子。二者关系：

| 项 | 是不是注册表内容 | 处理 |
|---|---|---|
| 字段 `close` / `funding_rate` | 是 | 进注册表，受 C17 约束 |
| 算子 `ts_mean` / `rank` | 是 | 进注册表，受 C16 约束 |
| 因子 `KMID` / `ROC5` | **否** | 是「用注册表里的算子写成的表达式」，整批声明、整批计数（`02-mining-interface.md` §11） |

实测边界（`07-components.md` §4.2）：Alpha158 **158/158 可用**（补 `vwap` 后 17.3 ms 全量算完）；Alpha101 缺 `cap` / `industry`，Alpha191 缺 `hml` / `mkt` / `smb`，**均不可用**。它们的名字不得出现在内置因子清单里——列出来就等于承诺能挖。

## 7. 加一个字段 / 一个算子要动什么

| 动作 | 谁批准 | 算什么 | 需要同步改的 |
|---|---|---|---|
| 加一个已存在供给的字段（如 `basis`） | 不需要新增代码，只改配置声明 | 新试验族（搜索空间变了） | 字段注册表 + 面板列集（已开放，I35） |
| 加一个需要新采集的字段 | 供给链维护 | 新试验族 | 字段注册表 + 供给适配器 + 门禁 A |
| 加一个算子 | 能力层维护 | 新试验族（MQ1） | 算子表 + `operators_version` 变化 + 参考实现对拍 |
| 改算子语义（修 bug） | 升级 | 新试验族 | 版本 +1，旧产物 `stale` |
| 改字段 `available_lag` | **按新实验处理** | 新试验族 | 注册表 + 全部历史暴露失效 |

判据同上：**配置里会不会多出一个新名字？** 会 = 新增，要登记与预注册。

## 8. 不变量与验收

| 编号 | 内容 | 检查点 |
|---|---|---|
| **I40** | 表达式只能引用注册表内的字段与算子；注册表是编译期输入，不是文档约定 | C16 / C17；未注册名 → `E1015` / `E1014` |
| **I41** | 算子参数域包含符号与窗口方向；负位移、居中窗口、反向填充在编译期被拒 | 构造 `shift(-1)` / `center=True` / `bfill` → 三条各自 `E1015` |
| **I42** | 退化输入不得用常数替换；常数暴露整批拒绝 | 全零因子入库 → `E2004`；`std > 1e6` 的快照不得通过 |
| **I43** | `operators_version` = 算子表内容哈希；`fields_digest` = 字段表内容哈希 | 只改表内容不改包版本 → 两个指纹都必须变 |
| **AC40** | 注册表可机器读 | 从注册表导出的字段清单与面板实际列逐项一致；差一项即失败 |
| **AC41** | 注册表自检 | 给算子表注入一条非法条目（空窗口 / 负位移）→ 注册表加载失败，而不是运行时才炸 |
| **AC42** | 因果禁令覆盖常见写法 | `shift(-1)`、`center=True`、`bfill`、`pct_change(-1)` 四种写法全部 `E1015`，且消息含算子位置 |
| **AC43** | 常数与爆炸防护 | 全零因子、`std > 1e6` 的暴露各构造一例 → 均被拒绝，且拒绝原因可读 |

## 9. 反模式

1. **在算子表里加一个「方便」的 `future_return`**：它不是算子，是标签，只能在 Target 工位出现。
2. **把 `vwap` 留给大家各算各的**：同一份数据出现两种 vwap，因子不可比。
3. **用 `try/except` 兜住缺列返回 NaN**：NaN 会一路传到 `rank()` 变成噪声排名，而不是报错。
4. **在注册表里塞业务规则**（如「资金费必须按 8 小时」）：注册表只描述**能引用什么**，口径归 `caliber`。
5. **文档里维护一份手抄算子表**：必然与代码漂移；文档只描述结构与规则，清单由代码导出。
